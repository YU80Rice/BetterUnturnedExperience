## Question

V1 旧插件"兼容接收/运行"的具体机制是什么：数字频道如何继续工作、何时退出？

## 决策要点

1. 兼容接收/运行的具体含义：旧插件用数字频道与 BUE 网络模块通信的映射/桥接方式。
2. 兼容边界：BUE 只为既有 V1 消费方保留兼容能力，不再提供新 V1 注册入口（CONTEXT.md L65-67）。
3. 退出条件：V1 兼容过渡期在主要官方功能和主要生态插件完成 V2 迁移后结束（CONTEXT.md L101-103），由迁移覆盖率决定——本票要定"如何测量覆盖率"。
4. 兼容实现放哪：BueNetworkApi 内？独立兼容层？故障时行为？

## 答案

### 第一轮（兼容机制）

- **Q1 兼容粒度 = A**：旧插件（用 LMN V1 API 的插件）在 BUE 环境下**无改动运行**——BUE 提供 V1 兼容层模拟旧注册表；不只是"能解析 V1 帧不崩溃"。
- **Q2 兼容层形态 = C**：帧识别在 BueNetworkApi 接收面（T3 Q7-C 独占），同时"是否启用 V1 兼容"作为**官方功能**（玩家可在面板关），符合"官方纳入后的可选功能"（CONTEXT.md L33-35）。
- **Q3 旧插件声明方式 = C**：旧插件**二进制不动**；BUE 接管时拦截/接管 LMN 的注册入口，使旧插件的注册调用落到 BUE 兼容层——这是"吃掉"的技术实质（联动 T5 停用独立 LMN）。
- **Q4 退出条件 = C→A**：现阶段已知生态插件清单未知；先定"度量方式 = 官方功能全 V2 + 已知生态插件迁移比例"，具体阈值等生态盘点（T8）后定。
- **Q5 故障行为 = A**：V1 兼容层故障只丢弃 V1 帧 + 诊断，V2 频道与本地功能不受影响（V1 是过渡兼容，不该拖累 V2）。

### 第二轮（联动与验收）

- **Q6 V1 帧格式基线 = A**：Host 内部文档/代码注释固化 V1 帧结构（不进 Contracts），注释写明来源（LMN 源码行号），代码即规范。
- **Q7 生态盘点 = A**：建 research 票 T8（V1 数字频道生态插件 + 迁移状态盘点），与 T5 并行跑。
- **Q8 验收标准 = A**：干净环境装 BUE + 旧 V1 no-op 插件（用 LMN V1 API 编译的 fixture），**插件不改代码能收发**（实机或主机测试）；否则兼容是纸面承诺。
- **Q9 与 T5 依赖 = A**：接管停用独立 LMN（T5）先于兼容层生效；否则双网络实现同时跑，违背 CONTEXT.md「网络能力接管」L69-71。

### 依赖

- T5（LMN 共存接管机制）——顺序依赖：先接管停用，再落兼容层。
- T8（V1 生态盘点 research）——为 Q4-A 的迁移比例阈值提供数据。

# 官方网络模块成熟度定级

Type: wayfinder:grilling
Status: resolved（2026-09-03 人工拍板）
Parent: V2 第一阶段：LMN 官方纳入与 BueNetworkApi（Wayfinder 地图）
Blocked by: 无

## Question

LMN 纳入后的 BUE 官方网络模块，归入"核心 / 可选 / 实验性"哪一级？

## 决策要点

1. 分级规则（CONTEXT.md L41-51）：核心和可选默认启用、实验性默认关闭；分级决定默认启用和稳定性承诺，不改变兼容/回退/隔离约束。
2. LMN 网络模块的定位：默认启用（CONTEXT.md L73-75「BUE 网络模块默认策略」已定默认启用）——但默认启用与"核心/可选"不冲突（核心、可选都默认启用）。
3. 定级考量：网络层是基础设施（偏核心）还是可替换组件（偏可选）？与官方功能"玩家可关闭"义务如何协调？
4. 故障隔离联动：核心级故障触发全局安全降级 vs 功能级故障只隔离该功能——网络模块定级直接影响这个边界。

## 答案

- **Q1 定级**：官方网络模块归 **核心**。用户描述 BUE 与 LMN 的关系为"BUE 吃掉 LMN 然后消化，变成自己专属的网络层"——LMN 不是可替换组件，是平台地基的一部分，故按核心对待。
- **Q2 故障边界（拆开处理）**：网络模块归核心，但网络层故障**只隔离网络功能，不触发全局核心安全降级**。用户确认：其他本地功能（如 BII）只是接管玩家本地物品摆放交互，不向其他玩家/服务器发消息，已在 U3DS 验证中证明不受网络故障影响。
- **Q3 分开定级**：官方网络模块（可关，玩家可在面板关闭）与 BueNetworkApi（核心运行时基础设施，不参与面板开关，像 Contracts 一样常驻）**分开**对待。
- **Q4 确认**：正式决议 = 网络模块**核心**（默认启用 + 稳定性承诺）、BueNetworkApi **核心基础设施**（不参与面板开关）、故障边界 = **网络层故障仅隔离网络功能**。
- 与 CONTEXT.md 既有规则协调：L73-75 默认启用 ✓；L53-55 功能级故障隔离 ✓；L94「网络模块故障时本地功能仍可用」✓（拆开处理不冲突）。

## Question

如何把光标位置映射为确定性候选格位，并在保持方向、自动旋转、边界、占用、容器尺寸变化和提交竞态下给出可解释且与最终提交一致的结果？需要一个可运行的算法原型验证体验与不变量。

## Comments

### 2026-08-24 人工体验反馈

人工开发者否决“只要当前方向在整个容器任意位置还有解，就不尝试自动旋转”。该规则会把 2×3 吸到远处，而忽略鼠标附近可容纳的 3×2。

修订候选规则：允许自动旋转时，当前方向与 90° 方向都计算各自最近合法候选；比较候选中心到光标的平方欧氏距离，距离更近者获胜；距离完全相同时才优先保持当前方向，随后按 Y、X 确定性裁定。原型已增加“2×3 自动转 3×2”场景，等待 Gemini 复核与最终人工确认。

### 2026-08-24 Gemini 与人工开发者联合复核

联合复核否决上述“双方向无差别距离竞争”，因为空旷区域中 2×3 与 3×2 的中心相位差会导致方向高频翻转和视觉蠕动。

最终候选规则改为 Local-Fit Priority：

1. 局部投影能放当前方向时立即返回，绝不检查旋转。
2. 局部当前方向失败、局部旋转方向可放时就地旋转。
3. 两种局部投影都失败后，扩大搜索先当前方向。
4. 当前方向全局无解时才扩大搜索旋转方向。

该联合反馈是当前最终输入；前一条“双方向距离竞争”仅作为已否决的原型历史保留。

## Answer

完整决策见 `../Item-Placement-Algorithm-Spec.md`，可交互一次性证据见 `../prototypes/12-item-placement-logic-prototype.html`。

最终算法冻结为 Local-Fit Priority：

1. 光标局部投影能放当前方向时立即返回，绝不检查旋转。
2. 局部当前方向失败、局部旋转方向可放时就地自动旋转。
3. 两种局部投影都失败后，扩大搜索先当前方向。
4. 当前方向全局无解时，才扩大搜索旋转方向。

局部投影使用 `floor(cursor - footprint/2 + 0.5)` 并执行边缘 clamp；局部半格按正方向舍入。扩大搜索使用候选中心平方欧氏距离，距离相同按 Y、X。两种规则属于不同层级。

光标出容器返回 `Hidden/OutsideGrid`；至少一个尝试方向尺寸可容纳但全部被占用返回 `LocallyInvalid/Occupied`；所有尝试方向尺寸均不容纳返回 `LocallyInvalid/OutsideGrid`。V1 不产生 `NoCandidate`。

生产 C# `Evaluate` 必须无状态、无 Unity 副作用且热路径零分配；当前 HTML 和 Node 烟测只验证行为，不能证明生产零 GC、游戏手感或三环境运行。

人工开发者与 Gemini 联合确认该阶梯是消除空地横竖“蠕动”、同时保留障碍狭缝自动旋转的最终设计。独立全范围审计 PASS，阻断项 0。

### 2026-09-01 人工开发者决议（R4 实机反馈 → 自动旋转对称语义 + 空位边缘贴边）

R4 实机（背包 5×7 / 后备箱 6×3，`UMM-诊断包_20260901_223854`）复现：武士刀（1×3）"竖→横"自动旋转成功后，重新拿起横武士刀拖回"竖着的位置"不自动转回竖，必须手动按 R。3×3 窄缝红测证明 evaluator 在"横放确实放不下"的窄缝能转回竖（绿）；真实失败原因是宽容器中横放（3×1）局部几乎总能放下 → 阶梯①永远命中。

经 `/grill-me` 多轮访谈（Q1/Q3/Q5/Q7/Q9/Q10/Q11/Q12/Q13），人工开发者冻结决议（完整记录见 `docs/adr/0003-bue-auto-rotation-edge-fit-decision.md`）：
1. 保持 Local-Fit Priority 阶梯①（当前方向局部能放立即返回，绝不检查旋转）与防蠕动否决（L22-31）不变；
2. 自动旋转是预览层建议，提交走原生 `sendDragItem`；手动 R 随时覆盖；
3. 重新拿起已摆放物品时 `dragJar.rot` 保留放置旋转（U3-SDK `onGrabbedItem` L1121 `dragFromRot = dragJar.rot`），BUE `CurrentRotation` 链路正确（非 0）；
4. 新扩展：当前方向放不下且光标位于**空位区域边缘**（被物品挡出的可用连续空位边界，非容器物理边界）时，允许自动旋转并使**长边顺着边缘方向贴边**；仅在阶梯②已满足时参与判定，不引入独立边缘翻转源（防蠕动）。

关联：本决议是 Local-Fit Priority 的受控扩展；`CONTEXT.md` 词汇"自动旋转"定义不变。回归锚定红测见 `tests/BetterUnturnedExperience.Plugin.Tests` 的 `--dev16d-r13-symrot-red` / `--dev16d-r13-symrot-wide-red` / `--dev16d-r13-edge-rot-red`。

### 2026-09-02 人工开发者决议（R5 实机反馈 → edge-rot 升级为边缘感应带）

R5 实机（`UMM-诊断包_20260902_085838`，部署 R4 edgefix `3AF8DC...`）复现：单列 `LongSideHugsEdge`（`x==0`/`y==0`）触发过窄，且横武士刀一旦经 edge-rot 转横、重抓后 `dragJar.rot=1` 使阶梯①在开阔区永久锁死横向（"单向粘滞"）。经前端交互实测与三角洲收纳机制对比，人工开发者经 `/grill-with-docs` 拍板（Q-A~Q-D + Q1-Q6，完整记录见 `docs/adr/0003-bue-auto-rotation-edge-fit-decision.md` Revision 2026-09-02）：

1. **拒绝全局 BaseRotation 记忆**：朝向切换 = 几何空间与边缘引力驱动，非历史记忆驱动。
2. **边缘感应带**：带宽 `band(dim)=clamp(1.0, dim*0.15, 2.0)` 格，按轴独立（竖向带用 `containerWidth`，横向带用 `containerHeight`）。
3. **角落裁决**：重叠区保持当前进入姿态，重叠区外平滑接管（"往上一提立起，往下一拉躺平"）。
4. **判定基准**：光标网格坐标触发 + 物理容纳守卫（`rotatedFitsGrid && Fits`）。
5. **提交持久化保持**：松手用预览 `Candidate.Rotation`。
6. **D2 红线保持**：开阔正中部严格保持当前方向；`--dev16d-r13-symrot-wide-red` 断言不翻转。
7. **障碍边界引力保留**：`RowFullyBlocked`/`ColumnFullyBlocked` 空位边界与容器外壁等价，允许前序物品充当"人造侧壁"并排竖放。

回归锚定红测：`--dev16d-r13-symrot-wide-red`（D2 守卫保持绿）、`--dev16d-r13-edge-rot-red`（扩为感应带断言）、`--dev16d-r13-corner-lift-red`（新增，左下角上提转竖贴左壁）。

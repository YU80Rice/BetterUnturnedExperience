## 问题陈述

当前设计要求功能作者把源码贡献到同一个聚合 DLL。这样框架控制力很强，但没有准确表达目标：BUE 应当是运行在 BepInEx 之上的大型前置框架插件，自己提供官方功能，同时为独立功能插件提供公开运行时。

当前边界还容易造成一个错误预期：每个功能作者都必须重复整个框架的单人、SteamP2PFriends 与 U3DS 兼容性研究。BUE 应通过公开稳定契约、SDK、兼容测试套件、生命周期规则、统一设置接入和环境适配指南，消除框架基础设施层面的迷雾。但这不等于某个功能的具体玩法行为会因为 BUE 已经测试过，就自动获得运行通过或发布授权。

LMN 可以作为参照：它提供开放、可复用的插件网络框架；BUE 则是更大的宿主框架，不只负责网络，还负责模块加载、公开契约、生命周期/隔离、设置、能力协商、环境适配、统一 UI、诊断和兼容测试。LMN 仍然是可选传输适配器，而不是 BUE 的定义本身。

## 解决方案

把 BUE 定义为运行在 BepInEx 之上的公开前置框架插件与功能宿主。BepInEx 继续负责最低层的插件发现和程序集装载；BUE 负责更高层的公开契约、功能注册、生命周期、设置、兼容性和统一管理运行时。玩家把 BUE 与独立功能 DLL 并列安装，功能 DLL 声明依赖 BUE；BUE 不替代 BepInEx，不直接装载任意 DLL，不扫描任意程序集，也不通过反射猜测功能类。

运行时产品分为：

- `BetterUnturnedExperience.dll`：玩家安装的 BepInEx 前置框架插件，包含公开 Contracts、运行时注册表、生命周期/隔离、设置聚合、传输适配器、统一管理 UI 和官方功能模块。
- `BetterUnturnedExperience.SDK`：开发者使用的模板、Definition Linker、分析器、兼容测试和文档仓库。若其类型已转发到稳定 BUE API，运行时不要求额外安装 SDK DLL。
- 官方功能模块：V1 官方功能由项目维护，包括“更好的物品交互”，随 BUE Host 一起发布，拥有独立 FeatureId 和定义记录；玩家不需要额外安装第二个官方 DLL。
- 第三方功能 DLL：其他作者独立版本化的 BepInEx 插件，引用公开 BUE API，声明 BUE 为前置依赖，并在启动时显式注册。
- 可选客户端 UI 卫星 DLL：需要 Glazier/Sleek/Unity 的客户端表现层可以单独发布；U3DS 核心加载不依赖它。

最高测试 Seam 是**显式功能注册与统一管理运行时**：注册验证 → 不可变 Runtime Catalog → Feature Load Gate → 功能作用域 Bootstrap → Settings Facet/Snapshot 聚合 → 生命周期隔离 → Headless 门禁。

### 产品验收结果

- 玩家可在 BepInEx plugins 目录并列安装 `BetterUnturnedExperience.dll` 和一个或多个独立功能 DLL；没有功能 DLL 时 BUE 仍能运行。
- 已接受的功能会出现在 BUE 管理列表中，显示身份、版本、状态、设置、兼容性和安全诊断。
- “更好的物品交互”继续作为第一个官方功能，并继续使用 Unturned 原生库存权威链。
- 第三方作者无需修改 BUE 源码、复制 BUE 内部类、实现自己的设置菜单或生命周期协议，即可开发兼容功能。
- BUE 的框架兼容性证据只证明框架 Seam；每个功能仍需为自身行为和声明的环境提供针对性证据，不能自动继承 BUE 的玩法 PASS、发布授权或原生权威正确性。
- 声明错误、不兼容或运行失败的功能应在进程仍可安全继续时被拒绝或隔离，不得阻止 BUE、其他已接受功能和原版玩法继续工作。

## 实施决策

- 将“源码贡献进一个聚合 DLL”从唯一外部接入模型改为显式 BUE 功能注册；官方功能仍可继续使用内部聚合构建。
- 继续分离 FeatureId、身份状态、定义产物、Settings Facet、功能 Bootstrap、生命周期、能力和证据事实源；不得恢复运行时 Describe 或任意 FeatureId 查询。
- 使用 BepInEx 明确声明的插件依赖/入口作为发现 Seam；BepInEx 负责发现和装载，BUE 接收入口显式注册；禁止 BUE 使用 `Assembly.GetTypes()`、全目录扫描、类名猜测、直接装载任意 DLL 和全局 `PatchAll()` 发现功能。
- 每个功能核心 DLL 使用生成的 BepInEx 入口和生成的 BUE 注册调用；入口通过 BepInEx 声明依赖 BUE，待 Host 就绪后注册。
- 允许可选客户端 UI 卫星入口；核心 DLL 必须在 client/U3DS 引用交集中，卫星 DLL 必须进程门禁并单独注册。
- 定义稳定公开的注册契约，包含生成的定义产物、API 兼容范围、模块工厂、静态 Settings Facet、依赖/能力、环境意图和可选 UI 注册标识。具体字段属于后续共享契约变更，必须经 Gemini 复核。
- 在 Runtime Catalog 和 Runtime Feature Admission 激活前冻结注册；冻结后注册必须拒绝并要求重启。
- 以 FeatureId、schema 版本和 digest 确定性组合已接受功能；重复身份、API 不兼容、产物非法、缺少必需依赖和非法引用均 fail-closed。
- BUE 拥有统一管理 UI；功能提供静态描述和快照，不提供任意设置窗口。客户端 UI 扩展必须显式、可隔离、可卸载。
- 使用功能作用域生命周期和资源登记；功能异常只隔离该功能，核心不变量失败才进入 Core SafeMode。BUE 不承诺进程级沙箱，DLL 仍拥有宿主进程权限。
- 发布框架兼容测试套件。框架测试一次覆盖注册、Catalog、设置聚合、生命周期隔离、Headless Token 门禁和传输 Seam；功能作者负责自己的玩法和声明环境测试。
- 保持原生库存权威边界不变；库存功能仍走原生链，不创建平行库存协议。
- 发布包元数据和文档必须区分框架兼容性与功能行为兼容性。
- 当前 DEV-09 的单一 BepInEx 入口只代表 BUE 框架插件入口，不代表 BUE 替代 BepInEx，也不代表所有功能必须源码聚合进该 DLL。

### 后端复核要求（实现前必须闭合）

- 用户部署模型和开发程序集拓扑是两种不同事实。开发期可以保留 Contracts/Core/ClientUi/Transport 多项目，但正式 BUE Host 部署必须冻结物理产物模型。V1 推荐把公开 BUE ABI、核心运行时和官方功能源码聚合为 BUE Host 程序集；外部功能 DLL 不得依赖未声明、未随包安装的 Contracts/Core 运行时 DLL。
- 公开注册契约属于共享契约变更，不能只写成实现备注。必须冻结注册者、不可变定义产物、可执行工厂分离、BUE dependency identity、兼容范围、稳定拒绝错误族、注册线程、生命周期代际、晚注册行为和客户端 UI token 语义。工厂是运行时可执行输入，不能序列化进定义产物。
- 注册必须遵循显式阶段：`HostStarting → RegistrationOpen → CatalogFrozen → RuntimeReady`。只有 `RegistrationOpen` 接收注册；功能 `Start` 由 BUE 在 Admission 后调用，不能在功能自己的 BepInEx `Awake` 中直接启动。
- 客户端 UI 卫星是独立部署资产。U3DS profile 必须从部署层排除它；运行时 batchmode 检查只是必要条件，不是充分的结构隔离。若仍使用单一物理 DLL，必须补齐 IL/类型 Token 和真实 U3DS 装载证据。
- 功能隔离只从 BepInEx/CLR 成功装载且 BUE 收到注册后开始。装载前、类型解析和静态初始化失败必须由 SDK/CI preflight 提前拒绝，不能冒充运行时 `Isolated`。
- 发布证据必须绑定完整不可变 `LoadSetIdentity`：BUE Host 哈希、每个功能 DLL 哈希、可选 UI 卫星哈希、定义/产物摘要以及 reference/toolchain 身份。支持外部模块后，单一 DLL 哈希不够。
- SDK 只提供编译期工具。第三方运行时只依赖 BUE Host 的稳定公开 ABI，SDK 不得变成玩家必须安装的运行时依赖。
- 当功能 Core DLL 已加载、但可选 ClientUi 卫星缺失或初始化失败时，BUE 必须投影稳定的表现降级状态（候选标签包括 `PresentationDegraded` 或 `HeadlessOnly`），同时继续由 BUE 自己的设置界面渲染和编辑该功能的 Settings Facet。
- BUE 统一设置界面拥有原生 UI 树的主权。外部功能只能提供静态 Settings Facet，不得向设置模态窗注入原始 Glazier/Sleek/Unity 控件；自定义 HUD 或玩法表现必须使用明确的客户端 UI 卫星注册 Seam。
- 官方“更好的物品交互”必须与第三方功能使用完全相同的公开注册、生命周期、设置和隔离 Seam。官方发行版可以物理内置它，但不得使用隐藏的特权运行时路径。
- Shared Contract Change Request 是生产实现的硬前置条件，必须冻结注册、Catalog entry、客户端 UI 卫星和表现降级投影，同时保持 DEV-01～DEV-08 契约稳定。

## 测试决策

- 以显式注册与统一管理运行时为最高 Seam；不测试被禁止的私有反射扫描。
- 覆盖注册成功、重复身份、非法 FeatureId、API 范围不匹配、缺依赖、能力不匹配、digest 错误、UI Token 泄漏和晚注册。
- 打乱插件加载顺序并重复启动，验证 Catalog 确定性。
- 验证没有功能 DLL 时 BUE 可运行，一个坏功能不会阻止其他功能或原版回退。
- 覆盖 Settings Facet/不可变 Snapshot、策略覆盖、revision 冲突、迁移和卸载清理。
- 覆盖生命周期启动、停止、隔离、幂等清理和依赖级联。
- 使用 core DLL 和 UI 卫星 DLL 做 Headless 加载测试；静态 IL 扫描和真实 U3DS 加载仍是分开的门禁。
- 覆盖客户端 UI 卫星缺失、晚注册、重开、代际失效和安全销毁。
- 覆盖 API 小版本兼容和主版本拒绝。
- 框架兼容测试可绑定同一 CandidateBuild 在 SP、SteamP2PFriends Host/Client、U3DS 的证据；不能将其当成功能玩法证据。
- “更好的物品交互”继续单独验证原生权威、落点预览和投影收敛，并绑定自身 DLL 哈希和 CaseId。
- 在干净 BepInEx 安装中验证 BUE Host 物理部署，不允许存在未声明的 Contracts/Core 运行时依赖。
- 验证注册阶段顺序、RuntimeReady 前的排队、CatalogFrozen 后拒绝，以及打乱 BepInEx 插件加载顺序后的确定性。
- 验证缺失引用、目标框架错误、UI Token 泄漏和静态初始化风险能在 BUE 隔离 Seam 之前被 preflight 拒绝。
- 验证复合 `LoadSetIdentity` 绑定，拒绝由不同 BUE/功能/卫星哈希拼装出的证据。
- 验证 ClientUi 卫星缺失或失败时，功能进入表现降级，但 Settings Facet 仍可由 BUE 设置中心渲染和编辑。
- 验证第三方功能不能向统一设置模态窗注入原生 UI 控件，并验证官方“更好的物品交互”使用同一公开注册 Seam。

## 不在范围内

- 对任意第三方 C# 代码提供强沙箱或安全隔离。显式安装代表信任决定；BUE 只能做契约校验和可恢复故障隔离。
- 自动扫描 plugins 目录中的全部 DLL 或按类名发现。
- 在 Contracts/Core 暴露 Glazier、Sleek、Unity 类型。
- 替换 BepInEx 加载器、绕过其依赖模型，或修改 Unturned、U3DS、LMN 和客户端原版内容。
- 让所有第三方功能自动继承 BUE 的运行 PASS、发布授权或原生玩法正确性。
- 自动交换、重排或平行库存权威。
- 运行期间热替换功能 DLL。
- 外部 Web 服务、数据库或远程模块市场。

## 补充说明

- 本提案有意与当前 Wayfinder 的“V1 不动态加载外部功能 DLL”冲突。在本提案接受前，旧表述仍是有效基线，DEV-01～09 不被追溯性改写。
- 获批后的第一工作包应是架构变更审查和共享契约变更请求，然后制作注册/Catalog 原型。
- 获批后的首个实现应是无操作外部功能夹具，再将“更好的物品交互”迁移到同一公开注册 Seam。
- BUE 可以为后续作者扫清基础设施迷雾，但不能替作者验证其自身原生 Hook、网络行为、性能和环境声明。

# V4-T2 未保存草稿与配置保存

- **Ticket**: V4-T2
- **Type**: grilling（决策票，HITL；必调 grilling + domain-modeling）
- **Status**: resolved（2026-09-11 Q21–Q34 定音）
- **Blocked By**: V4-T1, V4-R1
- **Map**: [map.md](../map.md)

## Question

开图已定主干：详情页可改项进未保存草稿；点「保存配置」才交给权威源；关面板或换条目时若脏则确认「修改尚未保存，要保存吗？」；收藏仍即时。本票把草稿做成可实施的界面语义（不写代码）：

1. **草稿范围边界**：BUE 设置、功能级启停意图、外部可编辑 ConfigEntry 已收。只读行、状态标签、网络接管提示是否永远不进草稿？外部「需要重启」项进草稿后，保存成功是否立刻标脏「须重启」？
2. **确认弹窗三按钮**：保存 / 不保存 / 取消 的精确后果（权威源写什么、画面回哪、草稿丢不丢）。换条目、关面板、刷新、游戏 UI 树重建（Glazier 重挂）是否同一套？
3. **部分失败**：一次保存里 BUE 设置成功、启停失败、或某条 ConfigEntry 抛错——整单回滚、还是成功的留下失败的留草稿？失败如何显示？
4. **校验拒绝**：SettingsRuntime 校验失败（过期 revision、非法值）是阻止保存并留草稿，还是保存按钮不可点？与现有「BUE 设置已保存。」文案如何替换？
5. **并发**：面板开着时功能被隔离 / 外部插件卸载 / 设置被别处改 revision——草稿是作废、合并、还是保存时 Occupied/过期拒绝？
6. **Headless 与无面板路径**：无 Glazier 时草稿不存在；是否禁止任何后台自动保存？

事实输入：V4-R1（当前是改一项就写）。对照 ADR-0002 第 5、9 条（SettingsRuntime 权威、可编辑类型边界）。

## Answer

2026-09-11 用户 Q21–Q34 全部定音。本票交付=未保存草稿与配置保存的界面语义 module：草稿范围、确认三选一、跨源部分成功的画面、校验/并发失败、保存顺序与脏判定。不写生产代码。T1 的逻辑面板会话、设置提交原子性、跨源部分成功、U3DS 不建草稿不重开。

### Q21 — 草稿范围

进草稿：`ClientPreference` 设置、功能级启停意图、外部允许编辑的配置（含 `RequiresRestart` 项的**值**）。

永远不进：只读行、功能/表现状态、网络接管提示、加载/隔离/缺 ClientUi 等投影、收藏、**`ServerAuthority`（Q32）**。

`RequiresRestart` 保存成功后立刻显示「需要重启」徽章：表示**已写入、须重启才完全生效**，不得再标「未保存」。

### Q22 — 确认三按钮

原文（Q34）：「修改尚未保存，要保存吗？」按钮：**保存** / **不保存** / **取消**。无强制覆盖。

- **保存**：等同「保存配置」。相关源全部成功才继续关面板或换条目；任一源失败则留在本条、失败草稿保留、**不导航**。
- **不保存**：丢掉本条全部草稿，再关或换。
- **取消**：不关、不换、草稿不动。

同一套确认：当前条脏时刷新列表（刷新会冲掉编辑画面）。**不确认**：Glazier 重挂、不结束逻辑会话的内部重绘。

### Q23 — 部分失败画面

顶上：「部分保存失败」+ 失败源与原因。成功行=新权威值、不标未保存；失败行=草稿值并标未保存；失败的启停意图留在草稿。「保存配置」只要还有未保存就可点。不整单回滚、不静默丢失败项、不另做进度条。同一 `SettingsRuntime` 源内部校验失败=该源整单拒绝，不允许源内半提交。

### Q24 — 校验与按钮

脏则保存按钮可点，不因「可能非法」灰掉。点下去才校验/revision/提交。该源失败：整单拒、revision 不动、草稿全留、不导航。

文案：全成功→「配置已保存。」；校验失败→「未保存：设置校验未通过。」+原因；revision 过期→「未保存：设置已在别处变更。」

### Q25 — 外部世界变化

不自动清空、不自动合并。隔离：状态标签实时变，启停意图留草稿，保存时按当时生命周期尝试，不允许则该源失败。插件卸载：对应 ConfigEntry 保存失败，原因「插件已卸载」，其它源可独立成功。revision 过期：该设置源拒写、草稿留、不覆盖；玩家须先「不保存」再改。本阶段无第四种冲突按钮。

### Q26 — 无后台自动保存

只有「保存配置」与确认框「保存」写权威源。改控件、刷新状态、重挂、闲置、退出、断线、Headless 均不静默写盘。无面板路径不创建草稿。退出时未保存草稿丢失；已保存内容由各权威源持久化。

### Q27 — 写入顺序

1. BUE 设置：本条全部草稿字段一次原子 `Submit`；
2. 外部 ConfigEntry：稳定顺序逐条写；
3. 功能级启停：最后应用。

启停不是「前面全部成功才执行」的事务尾。设置失败仍继续外部配置与启停（T1 跨源部分成功）。改成「任一失败跳过启停」须另立裁决。

### Q28 — 基准 revision

进入详情时记下 `snapshot.Revision`；本源保存成功后更新为新 revision。本源所有草稿字段用这一基准打成一次 `Submit`。过期则整源拒绝、草稿全留、其它源仍按 Q27 独立尝试。

### Q29 — 脏

草稿中任一可编辑字段与对应权威快照值不同即为脏。按最终值，不按是否按过控件。拨回原值→不脏。只改收藏、只读投影变化、外部世界变化→不因此变脏或变干净。

### Q30 — 全成功后画面

清空草稿；各行改权威值；去「未保存」；顶上「配置已保存。」；有 `RequiresRestart` 成功项则此时打「需要重启」；更新 revision 基准；不关面板、不换条目。确认框里点保存且成功后，才继续原本的关/换。

### Q31 — 不脏时按钮

按钮始终可见、不灰。不脏点击=成功空操作，不写权威源、不动 revision。文案：「没有需要保存的修改。」

### Q32 — ServerAuthority

客户端只读投影，不进草稿、不可编、不参与保存、不影响脏。客户端保存只处理 ClientPreference、启停意图、外部可编辑 ConfigEntry。U3DS 无面板、无服务端草稿。

### Q33 — 「未保存」标记时机

可编辑行一脏立即标「未保存」；改回则去掉；保存成功去掉；保存失败保留。只读/`ServerAuthority`/收藏不标。顶上失败横幅仅在点过保存且失败后出现，编辑中不打红条。

### Q34 — 确认框原文

「修改尚未保存，要保存吗？」三按钮保存 / 不保存 / 取消。无强制覆盖。

## Impact

- `CONTEXT.md`：收紧未保存草稿（不含 ServerAuthority）、配置保存（顺序+无自动保存）、新增「脏」。

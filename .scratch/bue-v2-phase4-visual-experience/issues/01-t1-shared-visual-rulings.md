# V4-T1 可视化体验跨表面共享裁决

- **Ticket**: V4-T1
- **Type**: grilling（决策票，HITL；必调 grilling + domain-modeling）
- **Status**: resolved
- **Blocked By**: —
- **Map**: [map.md](../map.md)

## Question

开图轮已把目的地、三块表面、不建 BueUi、两套目录、未保存草稿主干写进地图 Notes，本票不重开那些条目。本票只把**跨表面仍会分叉**的共享规则裁成可被 T2..T8 直接引用的裁决：

1. **契约影响**：描述、循环切换、功能级启停、未保存草稿，哪些进入公开契约（`IFeatureRegistration` / `SettingDescriptor` / SDK 文档），哪些只是 ClientUi 实现？若加契约，是否 Minor（2.1→2.2）？`public` ≠ 契约的纪律是否原样沿用？
2. **同权口径**：生态 BUE 功能与官方功能在面板上同控件、同草稿、同保存；外部 BepInEx 插件是第二目录，不是契约同权对象——此句是否冻结？官方先行消费在可视化上的检验点是什么（面板自身 / LIT 设置页 / NoOp 描述与 Choice）？
3. **Headless**：U3DS 无 Glazier 面板。本阶段验收是否只要求客户端可见表面，服务端只保证不画、不抛、不写脏草稿？
4. **草稿寿命**：未保存草稿是否仅活在当前面板会话（关游戏即丢）？是否允许跨开关面板存活？
5. **权威源纪律**：草稿不得成为第二设置事实源；保存失败时权威源与画面如何对齐（已写成功的留下、失败的留草稿）——确认或收紧。
6. **本阶段不做清单（共享）**：物品/配方/生物选择器、分类导航、路径调试信息、锁定页按钮、排序规则、BueUi——从共享规则再钉一次，避免后续票偷运进来。

每项输出：裁决条目 + 受影响的 CONTEXT.md / SDK / ADR-0002 条目（如需修订）。

## Answer

### Q15 — 契约影响

- 本阶段消费 2.1 已有公开契约：`SettingDescriptor` 的 `Choice`、`DisplayNameKey`、`DescriptionKey`、`AllowedValues`，以及既有的功能级启停缝；本阶段补齐数据投影与 ClientUi 控件，不因 `public` 可见就扩大契约。
- `IFeatureRegistration` 保持 2.1 的四成员形状，不新增破坏性成员。功能级长描述若仍需进入公开契约，只能在后续以可选 facet 或面板 chrome 的非破坏性方式提出，并由 T3 决定；若最终进入契约，版本按 Minor（2.1→2.2）演进，不能在本票中偷渡。
- 描述行、循环切换、保存按钮、确认弹窗、未保存草稿均属于管理面板 ClientUi 实现；未保存草稿不进入 SDK、不写入持久化设置。`public` ≠ 契约的纪律原样沿用。

### Q16 — 同权口径

- 官方功能模块与生态功能模块在 BUE 管理面板上使用同一套控件、同一套未保存草稿和同一套配置保存语义。
- 外部 BepInEx 插件保留为第二目录，接受本阶段的视觉升级，但不是公开契约的同权对象；不得为外部条目增加进程级功能启停或热卸载语义。
- 官方先行消费检验点冻结为：①管理面板自身完成草稿、保存和功能级启停；②LIT 设置页真实消费模式与方向两条 `Choice`；③NoOpFixture 带一句话描述和至少一条 `Choice`，证明生态注册路径可以出现在面板。NoOpFixture 不替代官方先行消费证明。

### Q17 — Headless

- 本阶段可视化验收只针对客户端画面。U3DS 不构造管理面板、不构造草稿、不自动保存客户端草稿，也不让未保存客户端草稿改写 `ServerAuthority`。
- U3DS 不武装 LIT 的 Glazier 注入，不依靠异常作为门禁；服务端必须不画、不抛、不留下脏草稿。功能默认启用与服务端权威设置语义保持不变。

### Q18 — 草稿寿命

- 未保存草稿只存在于当前逻辑面板会话的内存中：关闭面板或退出进程即丢失；若关闭时有脏改动，先执行“保存 / 不保存 / 取消”确认。
- 切换管理条目视为离开当前详情会话：有脏改动时同样确认，保存或放弃后不把草稿带到下一条目。
- Glazier 树重挂载不等于关闭逻辑面板会话；安全重挂期间草稿继续存在。收藏偏好仍按既有规则即时持久化，不能与草稿混同。

### Q19 — 权威源纪律

- 单一功能的一次 `SettingsRuntime` 提交保持原子语义：校验或提交失败时整次提交拒绝、revision 不推进，草稿保留；不得把部分字段写进 SettingsRuntime 后再用草稿补偿。
- 跨权威源的保存动作（例如 BUE 设置、`SetFeatureEnabled`、外部 `ConfigEntry`）不是一个事务：成功源保留已写结果，失败源留在草稿并明确显示失败原因。画面可以拼装“成功项显示权威值、失败项显示草稿值并标记未保存”，但草稿永远不是第二事实源，也不得绕过正式提交缝写入持久化文件。
- 并发或过期提交按既有 revision/冲突结果处理；细节由 T2 细化，不在本票重新定义。

### Q20 — 本阶段共享不做清单

本阶段不做：物品/配方/生物选择器、分类导航、程序集或配置路径调试信息、锁定页按钮、整理排序规则（O-LIT-1）、BueUi、外部插件热卸载、STORAGE 页注入。后续若要做其中任一项，必须先改 Phase-4 目的地，不能作为本票或后续票的实现细节偷渡。

## Impact

- `CONTEXT.md`：沿用 `可视化体验`、`未保存草稿`、`功能级启停`、`配置保存`，并补充 `逻辑面板会话` 与 `设置提交原子性` 的领域定义。
- SDK：本票不改 2.1 公开成员；只有后续明确决定增加可选 facet 时，才登记 2.2 的契约变化。
- ADR-0002：沿用“不在 Headless 构造 ClientUi”和既有设置/生命周期事实源纪律；无需重开 ADR。

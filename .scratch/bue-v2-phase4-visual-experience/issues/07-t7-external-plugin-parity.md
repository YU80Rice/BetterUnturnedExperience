# V4-T7 外部 BepInEx 插件目录的同等升级

## Question

开图已定两套目录同等升级，但外部插件不是契约同权对象（T1 将钉）。本票裁外部条目在描述、Cycle、草稿保存上的精确行为：

1. **描述**：BepInEx `BepInPlugin` 没有标准长描述。用什么（无则隐藏 / GUID 旁 tooltip 已有版本是否够）？
2. **ConfigEntry**：bool / 数字 / 字符串（ADR-0002）+ Cycle 标签 / AcceptableValueList。本阶段是否只加 Cycle，其它离散约束继续只读？
3. **保存**：与 BUE 草稿同一按钮；写 ConfigFile 失败怎么办；需要重启的提示时机（保存后 vs 改的时候就黄条）。
4. **检测到 UPM 本体**（`com.trae.pluginmanager`）：底栏「BUE 不会重复修改其状态」是否维持？其 ConfigEntry 还编不编辑？
5. **不做**：热卸载、进程级启停、ItemList/BlueprintList/CreatureList/Category 导航——再钉一次，避免和「同等升级」被读成「把 UPM 全搬过来」。

事实输入：V4-R1、ADR-0002。

## Answer

2026-09-11 用户 Q65–Q70 定音。本票交付=外部配置 adapter 的编辑形状与失败投影。识别标签 ≠ 赋予能力；写 cfg ≠ 控制加载状态。T8 已解锁。

### Q65 — 不画插件级长描述

外部插件不显示功能级长描述。详情头：名称、GUID、版本。配置行描述来自 `ConfigDescription.Description`，空则不画、不占位。不用 Name/GUID/tooltip 冒充长描述，不加入 chrome 对照表。

### Q66 — 两层：类型 vs 形状

**可编辑基础类型**：bool、数字、字符串。其它 CLR 类型 Unsupported 只读。

**Cycle 形状**仅当同时满足：值类型受支持、约束为明确识别的 `Unturned.Cycle` 或 `AcceptableValueList`、候选值非空且可完整写回底层类型。未识别的离散约束不变成选择器；底层仍属基础类型则用普通控件进草稿，不再因「有离散约束」整行只读。写入仍经 ConfigEntry 原有校验与回调；不执行任意代码、不热卸载。

### Q67 — RequiresRestart 两层提示

行级「需要重启」=该项固有属性，编辑前后都可显示，≠未保存，≠已写入。顶部「需要重启」徽章**仅针对本次保存实际成功写入的项**；写入失败只留草稿和失败原因，不打成功后的重启徽章。编辑不立即写盘。

### Q68 — 检测到 UPM

继续列出 UPM，受支持 ConfigEntry 按统一草稿/Cycle/校验/保存编辑。不卸载、不停用、不热替换、不隐藏 UPM 面板。底栏保留「检测到外部插件管理器；BUE 不会重复修改其状态。」此处「状态」=加载与运行状态，不禁止写受支持配置，也不承诺配置不重启就能完全生效。BUE 不为 UPM 处理热应用或配置迁移。

### Q69 — 本阶段不做

不做：热卸载、进程级启停、ItemList/BlueprintList/CreatureList 选择器、Category 导航、程序集路径、配置文件路径、外部插件功能级描述、任意自定义元数据契约、未识别标签的额外警告面板。未识别标签静默忽略；底层不受支持则只读。不把 UPM 快照视觉能力整包复制，不把同等视觉升级解释成同等生命周期控制。

### Q70 — 写入失败

该项草稿保留并标未保存；其它独立条目按保存顺序继续。成功项显示新权威值；失败项显示草稿值。面板只显示稳定短中文，由外部配置 adapter 按**结构化失败结果**分类，不匹配异常文本、不画堆栈：

| 情况 | 文案 |
|---|---|
| 插件卸载或条目失效 | 插件已卸载 |
| 文件/权限/锁定/adapter 写入失败 | 配置文件无法写入 |
| ConfigEntry 校验、转换或值域失败 | 值不合法 |

若实现能区分「内存已更新但持久化失败」，不得显示完全成功；若无法区分，按现有写入 seam 的失败结果处理并保留草稿，不在本票承诺第三种精确投影。

## 事实基线（已建成事实与本阶段缺口）

1. Phase-6 已把工程边界、官方消费者降权与发布闭包接到 2.1；当前玩家看见的仍是第五阶段玩法：行带整理、「备匣 N · 备弹 M」、2 级双击后再等 8 秒、自造技能分区、全局技能账、预放置代码有绿/红但实机可深色、自动旋转 `(rot+1) mod 4` 可选到倒置。
2. 整理：唯一策略仍是 `tagged-row-band-v1`。当前栏 / 全身 / 容器 / 入包恢复 / 快转接收侧共用 `ITidyStrategy`。20 档 `PlayerUseLabel` 枚举序保留。`inventorytidy.mode` 已退役；`direction` 仍画在面板并只翻稳定收尾。无独立右下评分。换方法会红掉行带几何钉。
3. 弹药 HUD：只挂 `UseableGun.updateInfo`。开火会刷新，背包匣/箱 amount 默认不刷新。N/M 不含枪上发数；观察 DTO 不读枪上弹量。箱侧与压弹共用 FillTargetItem / 口径谓词。
4. 压弹：功能 A = 整理后同 ID 合匣（本阶段保留不重开）。功能 B = 双击 R 用箱填身上五页未满/空匣。现网 2 级 = B 成交后再 8 秒同一套 B，枪在手只在指纹层，吃 1.5s 技术闸。
5. 换弹技能：自造 U 菜单分区，不能复用 `SleekSkill`（会绑 `Skill[][]`、走 `sendUpgrade`）。账在设置根全局 dat，键 steam × 角色显示名，无地图，故 PEI 点满带到 Washington。原版 `Skills.dat` 按 `serverID × characterID × 地图名` 分家。花费 125/150。
6. BII：Candidate→ValidGreen、LocallyInvalid→InvalidRed 已有 RGBA；`box==null` 或原版 `dragItem` 幽灵可盖住。自动旋转永远 +1 mod 4，从横会选出 `rot=2`。原版拾取只搜 0 再 1。ADR 0001 不增强拖出到地面。
7. 6.5 挂起：五页同一套、值观察四字段、三条权威提交分家、空集合不是成功——当官方功能内部纪律引用，不兑现为公开 seam。

## Problem Statement

玩家整理背包时，同类会被行带切散，大件旁边空着一整截，看起来不像「按用途归拢、从左上铺满」。弹药旁写「备匣 / 备弹」，开火能变、弹药箱却要开关背包才更新，也看不到枪上那发算进总数。换弹技能画成自造分区，进另一张图等级还在，和原版技能换图重置不一样；2 级也不是「点出来就会自己给背包匣填弹」，而是双击后再等一轮。拖东西时预放置框经常是深色，放不下没有红框；自动一转，步枪文字会变成「枪步」。

这些都是已经发布的官方功能手感，不是缺新功能。玩家要的是同一套整理、能信的总弹药、像原版的技能行、被动填匣、以及拖入时绿/红和正向图标。

## Solution

只优化已有三项官方功能，不新 FeatureId。背包整理换成唯一的标签归拢、组内大件优先、左上紧凑（`StableLabelCompact`）；更好的换弹体验把后备读数换成「总弹药」，开火和身上五页变化不晚于下一帧更新，技能行复刻原版结构并按地图×角色槽分家，2 级改为每 8 秒给身上五页空/未满匣填弹；更好的物品交互让可放绿、不可放红，自动旋转只在两个可读正向之间切换。玩家手册、对照表、Tooltip 与技能描述共用已冻结句子。

从使用者视角：点「整理」得到同类在一起、大件优先、左上紧凑、空位右下；瞄具下能读总弹药且打一发就变；U 菜单战斗区有一行像原版的换弹技能，换图会清零；2 级后背包匣会自己被弹药箱填上，仍可双击立刻压；拖入时绿框能放、红框不能放，图标不会倒过来。

## User Stories

1. As a 玩家, I want 点「整理」后同类物品按固定用途归拢、同一类里大件优先、从左上紧凑排列、空位留到右下, so that 我能靠位置记住东西在哪，而不是对着行带留下的空洞发愣
2. As a 玩家, I want 后一类只补前一类旁边还没围住的空格、不要把已经排好的同类切开, so that 「补边」不会变成又一种乱插
3. As a 玩家, I want 整理只使用两个正向、文字保持可读, so that 整理完步枪不会变成「枪步」
4. As a 玩家, I want 放不下时格子完全不动并看到原因, so that 不会出现「已经整理但漏了 N 件」
5. As a 玩家, I want 当前栏、全身、容器、入包恢复、快转接收侧用同一套排版, so that 换入口不会换摆法
6. As a 玩家, I want 设置里不再出现「整理方向」还能改结果, so that 我不会以为还有第二种算法
7. As a 玩家, I want 原版「当前/上限」还在，下面看到「总弹药」且 0 也显示, so that 我既知道这本匣满不满，也知道还能打多久
8. As a 玩家, I want 打一发或背包里匹配弹药变了时总弹药不晚于下一帧更新, so that 我不必开关背包等数字
9. As a 玩家, I want 总弹药含枪上匣、身上匹配匣和匹配箱，不含容器和地面, so that 数字和真正能压进背包的弹药一致
10. As a 玩家, I want 升到 2 级后每 8 秒自动给身上五页空/未满匣从匹配箱填弹，枪不在手上背包匣也填, so that 「自动压弹」是被动技能而不是再等一次双击
11. As a 玩家, I want 2 级时仍能双击立刻压弹, so that 被动周期不抢走手动
12. As a 玩家, I want 没箱可填时不要每 8 秒弹红字, so that 被动技能保持安静
13. As a 玩家, I want 整理后同 ID 合匣仍然发生、且和 2 级被动不是同一件事, so that 点整理不会被理解成被动压弹
14. As a 玩家, I want 在 U 菜单战斗区看到一行像原版的换弹技能（名称、级、描述、花费、整行可点、三格锁条）, so that 我不必学一套自造分区
15. As a 玩家, I want 换地图后换弹技能像原版技能一样从 0 开始, so that PEI 点满不会带到 Washington
16. As a 玩家, I want 0/1/2 的描述和手册说的是同一件事, so that 2 级不会再写成「双击后再等一轮」
17. As a 玩家, I want 拖入可放时看到绿色半透明框、不能放时看到红色, so that 我不用猜深色框算不算能放
18. As a 玩家, I want 自动旋转后图标仍正向可读，框、图标和松手朝向一致, so that 预览所见即所得
19. As a 玩家, I want 已经倒着的物品一被自动旋转就拉回能放下的正向, so that 「枪步」不会一直保持到我再按 R
20. As a 玩家, I want 开阔空地不要自己横竖乱转, so that 边缘贴边还在、中部不蠕动
21. As a 玩家, I want 手册、面板一句话、整理按钮悬停说的是同一套功能, so that 三处文案不会互相打架
22. As a Headless 服务端, I want 不画 HUD、技能行和预放置框, 但仍执行整理提交、被动压弹和技能扣经验, so that U3DS 有权威而不是只靠没画面
23. As a 联机主机, I want 被动压弹只在主机写背包、客机只看见同步结果, so that 客机 8 秒窗不能本地改格子
24. As a 仓库维护者, I want DEV-V7-02 独占弹药观察与匹配单源、03 只消费, so that HUD 和被动压弹不会各做一套口径表
25. As a 仓库维护者, I want 01..06 不授候选、07 出唯一对外候选且契约仍为 2.1, so that 台账身份唯一
26. As a 生态功能作者, I want 本阶段不要突然多出整理策略或预览契约, so that 我仍按 2.1 接平台，而不是接官方玩法

## Implementation Decisions

以下全部来自 V7-T1..T8 已裁决条目。冲突时以对应票 Answer 为准。本规格不发明新 FeatureId、不新增公开契约成员。

### 共享规则（V7-T1）

- **契约**：整理方法、总弹药 HUD、技能页、被动压弹、绿/红框、正向旋转全部落在官方功能 internal 或文档层。公开契约保持 2.1 零扩面。`public` ≠ 契约。6.5 内部解释当官方功能纪律引用，不兑现为公开 seam。
- **官方先行**：背包整理消费新整理方法；更好的换弹体验消费 HUD、技能页、被动压弹；更好的物品交互消费绿/红框与正向旋转。NoOp 不替代。生态不同权到这些业务能力。
- **四条旧不变量已授权重开**（授权 ≠ 未裁前可当已落地）：行带排版；2 级双击后再等一轮；全局技能账；自动旋转 +1 mod 4。新边界分别在下列各节。未实施前现网与玩家手册仍是第五阶段正文，实施票必须改到本规格。
- **Headless**：画面类（绿/红框、技能行、弹药 HUD、整理按钮外观）U3DS 不画、不抛、不写客户端草稿。权威类（整理提交、被动压弹、技能升级扣经验）U3DS / P2P 主机必须真跑。被动压弹即使枪不在手也必须由主机执行。
- **文档顺序**：CONTEXT 由对应决策票定音时已改。玩家手册由 DEV-V7-06 按文案票落地。SDK 本阶段不改。第三方评审不挡 `/to-spec`。实施交付仍走双轴独立审查。文案不得先于行为承诺未定机制。
- **功能 A**：整理后同 ID 合匣本阶段保留，不重开、不改语义、不与 2 级被动合并。
- **治本边界**：只改三项官方功能的玩家体验和内部实现，不把玩法债务伪装成平台能力，不用 UI 投影掩盖主机权威未兑现。

### 整理方法（V7-T2 → DEV-V7-01）

- 唯一官方方法 = 标签归拢、组内大件优先、左上紧凑。内部标识 `StableLabelCompact`，不进玩家界面、不进契约。废止行带放入规则与行带评分。不把 `tagged-row-band-v1` 伪装成新算法。
- **20 档标签顺序沿用**，不重开分类。单源仍是内部玩家用途标签枚举序。分类失败进「其他」，不得丢物。弹药箱按给弹匣供弹的蓝图关系识别，不能只凭 SUPPLY。
- **名单键**：标签序 → 固有面积大到小 → 固有最长边大到小 → 固有短边大到小 → 名称或物品 ID → 整理前从左上到右下原顺序。旋转不改变排名。
- **不拆散**：名单连续；同一标签已占用四连通；标签关闭后冻结，后续不得挤开或替换。补边只允许前一标签外轮廓或尚未围住的连续空位。不要求每个小件实例互相接触。阅读顺序连续不是否决补边的硬约束。
- **内部空洞** = 已被同类或已关闭区域包围、填进去会切断的洞。大件旁边尚未围住的空格是可用边缘（1×3 旁的 1×1 可填）。不是「主体定行高、右侧空着」。
- **放入**：按名单取物，选最靠上、最靠左、能放下且不造内部空洞的位置。默认正向；只允许两个可读正向。同一物品 ID 尽量同一方向。永不选 180°/270° 倒置。与 BII 共享正向产品定义，实现分家。
- **入口**：当前栏、全身、容器、入包失败恢复、快转接收侧凡背包整理都调用同一模块。入口只负责触发、范围、权限、会话和原版提交。快转源页恒等离场不是排版。
- **事务**：全部放下才提交；失败零提交。成功句与失败句见文案节。不为整洁而漏放。
- **direction**：描述符从面板移除。旧值可读以免存档解析失败，不再决定算法。完全相同则保留整理前顺序。标题栏仍只留「整理」。
- **结构优先级**（前项不同不再看后项）：全部放下 → 名单按标签连续 → 标签内大件优先且同 ID 归拢 → 内部空洞最少 → 从左上紧凑 → 空闲靠右下 → 后一类只补外边 → 同 ID 尽量相邻 → 默认正向同类方向统一 → 少旋转少无意义移动 → 完全相同保留整理前顺序。

### 弹药观察单源与总弹药 HUD（V7-T3 → DEV-V7-02）

- **DEV-V7-02 独占**弹药观察与口径匹配的唯一生产事实源。HUD 是消费者。被动压弹（03）也是消费者，不得反向依赖某个 HUD 表面类，不得复制口径表或库存观察。
- **公式**：总弹药 = 枪上匣当前发数 + 身上五页匹配匣发数 + 匹配箱发数。空匣贡献 0。不含容器与地面。无枪或无枪上匣时枪上贡献 0，不伪造枪。
- **两份事实、一套匹配**：枪上发数与原版弹药标签同一事实源。身上五页匣/箱复用压弹匹配（FillTargetItem / 口径谓词）。禁止第二套口径表。
- **表面**：原版「当前/上限」含义与字形保留，不覆盖。其下追加「总弹药 {0}」。持枪且功能运行时始终显示；0 也显示。位置沿用原版信息框左列下半。不改枪模小字，不占尸潮条。
- **刷新**：打一发，或拾取/丢弃/整理/压弹/合成导致身上五页匹配匣/箱变化，不晚于下一帧（宿主时钟同一拍或下一拍）。授权 LIR 内部观察缝（库存数量、枪上弹药）。不进契约，不另建第二套宿主泵。重新打开背包或再开一枪不得当刷新条件。只挂 `updateInfo` 不够。
- **生命周期**：切枪/卸枪/信息框销毁则总弹药行随框销毁。功能停用立刻回到裸原版当前/上限。U3DS 不画。

### 被动压弹（V7-T5 → DEV-V7-03）

- 只消费 DEV-V7-02 的弹药观察与匹配单源，禁止复制口径表或库存观察，禁止依赖某个 HUD 表面类。
- **时钟**：升到 2 级起算第一拍；之后每一拍从本拍尝试结束再等 8 秒。成功、无事静默跳过、与手动互斥跳过都算本拍结束。间隔固定 8 秒，本阶段不可设。
- **清窗**：死亡、切世界/存档、功能停用、等级降到 2 级以下。不补偿错过的周期。再满足条件则重新起算 8 秒。
- **范围**：一拍填身上五页（页 2..6）所有空/未满且有匹配箱可填的匣，各口径独立。不含容器、地面、装备槽、枪上匣。枪是否在手不改变背包范围。「无论武器是否在手」= 背包五页都填。
- **动作**：箱→匣填充，沿用功能 B 路径；不合匣、不拆别的匣。功能 A 保持独立。
- **互斥**：与手动双击事务冲突则本拍跳过，不排队、不抢占、不取消手动。不吃 0 级额外技能冷却。仍受同一条技术闸 / 原版写入锁；冲突跳过，不拆闸，不把技术闸包装成技能冷却 toast。0/1 级行为不变；手动仍是双击 R。
- **失败**：无匹配箱、无可填匣、已全满 = 静默。权威失败（漂移、权限、回滚）= 结构化主机日志，不向玩家每 8 秒打红字。必须是真实事务尝试，不能只记「应该压弹」。
- **权威**：主机写背包。客机不运行写库存的被动逻辑。U3DS 无画面也必须真压。客机经同步看见结果。总弹药走 02 观察单源下一帧跟上。不新增被动压弹成功网络事件。

### 技能行与换图清零（V7-T4 → DEV-V7-04）

- 依赖 03：2 级描述必须对齐被动压弹，不得先写出「双击后再等一轮」。并引用 R3/R5。
- **复刻、不复用**：不构造原版技能行对象，不走原版升级 RPC，不写原版技能数组。控件原语 = 按钮 + 图 + 字。必须有名称、当前级/满级、描述、花费或 Full、整行可点升级、0/1/2 三格锁条。经验不足整行不可点。不造职业小图标，不造条件加成。几何靠近原版行高 80 / 步进 90，不用现网 36 像素自造行。挂在 U 菜单战斗区下方，不插入原版槽。
- **名称与描述**（技能页、设置页、Tooltip 单源；手册可用文案节缩写，不得改含义）：
  - 0 基础：可双击换弹键立刻压弹；有额外技能冷却。
  - 1 快速换弹：取消额外技能冷却；防重复提交的技术闸仍然保留。
  - 2 自动压弹：每 8 秒自动为身上五页中的空或未满弹匣，从匹配弹药箱填弹；仍可双击换弹键立刻手动压弹。
- 花费仍 125 / 150。新档不送级。无三级、无超限按钮。
- **作用域**：账留在现有设置根，不写原版技能档，不新建第三套根。键 = `serverID × characterID × 地图名`，三者必须共同组成身份。`characterID` = 原版角色槽，不是显示名。同一世界多角色独立。客机只显示主机确认等级。沿用 LIT 熔断的设置根 + 地图×槽分文件方向。
- **旧账**：全局 `better-inplace-reload.skill-levels.dat` 不迁移、不复制、不作为新世界初值。每个世界/存档第一次进入从 0。无游戏内一次性弹窗。
- **表面**：战斗区成功挂载则只画那一处。探测失败才在本功能设置页显示同一套等级、描述、升级入口。两表面不得同时画，只共享同一账、同一主机授权、同一升级入口。U3DS 不画，也不因此改用设置页。表面失败不能变成另一套账或客户端自行升级。升级扣经验是权威行为，主机必须真跑。

### 绿/红框与两个正向（V7-T6 → DEV-V7-05）

- 不改原版拖入提交权威，不增强丢到地面，不建 BueUi。与整理共享正向产品定义，实现分家。
- **框**：只要半透明色块，不要描边。可放绿 `(0.2, 1, 0.3, 0.85)`；不可放（占用、越界、互换占用）红 `(1, 0.25, 0.2, 0.85)`。可放绝不是深色底。光标出网格或预览无效则隐藏。互换占用仍红：当前候选不可直接放置；松手是否原版交换不改变预览语义。凡已接管拖入的网格都画。原版深色框与未隐藏拖拽幽灵不得盖住 BUE 框。玩家只看见这一套。
- **正向**：拖入会话里的可读姿态。默认正向 = 进入拖拽时的原版基准（通常数值 0）；另一个正向 = 该基准再转 90°（通常数值 1）。不能机械把数值 0 当正向。正方形不自动旋转。自动旋转不能产生 180°/270° 倒置。
- **拉回**：已倒置且满足自动旋转条件时，拉回两个正向中能合法放下的那一个；两个都能放则遵守感应带与进入姿态；两个都不能放则红框，不伪造可放候选。手动 R 仍可暂时倒置。自动旋转不得把倒置当长期合法目标。
- **同一朝向**：框 footprint、预览图标、松手提交共用最终旋转。禁止框按新朝向、图标按旧朝向。禁止再叠一份旧朝向幽灵。横正向不是倒置。框与图标不一致、文字倒置、尺寸与 footprint 不一致都是缺陷。
- **感应带与防蠕动保留**：边缘感应带、开阔中部保持当前正向、障碍边界引力、角落进入姿态优先全部保留。停止使用 `(当前+1) mod 4`。需要竖选可读竖正向，需要横选可读横正向；开阔中部当前正向能放下则保持。ADR 0003 决策正文不整篇重写；Consequences 已记收窄。

## Testing Decisions

- 只测玩家/主机可观察行为，不测私有字段名或「调用了某内部方法」。红测先行：先有编译红或断言红，再实现。每票独立会话，双轴 CLEAN 后才关单。突变证红须含构建退出码与错误数，避免静默编旧二进制。
- **好测试**：同一输入同一布局；放不下零提交；标签连续与四连通可判红；总弹药数字在开火与背包 amount 变化后下一帧变化；被动周期到点后身上五页匣 amount 增加且枪上匣不在目标集；换地图后等级为 0；可放框不是深色底、不可放为红；自动旋转候选不含倒置；文案门禁逐字对齐本规格冻结句。
- **不要测**：内部类名、行带旧几何黄金坐标（01 必须改掉会钉行带的旧断言）、HUD 表面类被被动压弹引用、客机本地写背包成功。
- **模块**：01 排版纯域 + 五入口仍走同一策略标识；02 投影公式 + 刷新合同（开火与库存变化两条腿）；03 时钟/清窗/互斥/页范围；04 键三元组 + 不写原版技能数组 + 描述句；05 颜色与正向候选 + 框图标同 rot；06 手册/对照表/Tooltip 逐字；07 全套回归 + 三环境实机。
- **先例**：第五阶段 `AssertDevV502TaggedRowBand`、弹药 HUD 文案钉、换弹技能 4a/4b/4g、Placement 旋转红测、文案/手册门禁脚本。01 须把行带几何钉改成 `StableLabelCompact` 结构钉。05 须改掉硬断言倒置朝向为成功的竖 footprint 测试。02 须改掉「备匣/备弹」与「枪上无弹量字段」的旧钉。
- **红测组名**见上表。06 可用脚本门禁比对手册与对照表冻结句，不必只靠游戏内 UI 断言。
- **Headless**：画面类断言不画、不抛；权威类必须有主机侧可观察提交（整理结果、匣 amount、经验扣除），不能用「没画面」当过门。

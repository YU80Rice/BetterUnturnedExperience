## Question

更好的物品交互现网已有拖入预览、边缘感应带、自动旋转（ADR 0001 / 0003）。代码里预放置框已按 Candidate=ValidGreen、LocallyInvalid=InvalidRed 着色，实机用户看见的是深色框，无法放置也没有红框。自动旋转现网是 `(当前朝向 + 1) mod 4`，可以从「按一次 R」再翻到 180°，图标文字倒置（「步枪」看成「枪步」）。

开图已钉（本票不重审方向）：

- 只改玩家看见的拖入反馈，不重开管理面板、不新建 BueUi、不改 `sendDragItem` 权威（Q6）；
- 可放入格 = 绿色半透明提示框，不能放入 = 红色半透明提示框；占用和越界都红；深色原版框本阶段视为缺陷，要被绿/红取代，不保留第三种「深色可放」（Q13）；
- 自动旋转只允许在 `rot=0` 与 `rot=1` 之间切换；永不选 `rot=2` / `rot=3`；手动再按 R 仍可转到倒置；绿框、图标、提交朝向三者同一 `rot`（Q18）；
- 凡 BII 已经接管拖入的网格都画绿/红框；不画地面投放（Q19）。

用户对「自动旋转后图标」的期望句（Q14）：

> 自动旋转以后，图标会倒过来，我希望自动旋转以后的图标是「正的」，就是直接拾取进入背包后的那个方向，或者是按了一次 R 以后的朝向，物品以默认正向显示，旋转后物品上的文字、标识和图案必须保持可读。

R4（框为何仍深色）与 R5 不覆盖旋转；旋转事实在 `PlacementCandidateEvaluator`（`(rotation+1)&3`）与 `InventorySurfaceLifecycleAdapter`（`itemIcon.rot` / `isAngled`）。T1 须先授权收窄 ADR 0003 的 +1 mod 4。

本票裁决产品语义，不在本票改 evaluator：

1. **绿/红框**：半透明色块是否还要描边？色值本票钉还是留给实施（须可回归：可放绝不是 BACKGROUND 深色）？无法放置时红框画在光标投影格还是最近尝试格？互换占用（拖到另一件物品上准备交换）是绿、红，还是第三态？
2. **正向定义**：`rot=0` 是否就是「拾取进包的默认朝向」？是否存在资产默认 `rot≠0` 的物品，正向要以资产为准？正方形物品（宽=高）是否永不自动旋转？
3. **已倒置的物品**：玩家手动转到 `rot=2/3` 后再拖，自动旋转是保持倒置直到玩家按 R，还是一进入感应带就拉回 0/1？开图只钉「自动永不选 2/3」，拉回策略必须本票裁。
4. **图标与框**：框转了图标必须同一 `rot`、同一格、同一宽高。图标倒过来视为本阶段缺陷，不论是 rot=2 被选中还是 rot=1 时贴图锚点错。
5. **ADR / 词汇**：自动旋转词条是否改为「只在两个正向之间由边缘引力切换」？边缘感应带与开阔中部防蠕动（D2）是否原样保留，只是旋转候选从四向收成两向？
6. **不做**：改提交权威；增强拖出到地面；管理面板色板；把预览做成新 FeatureId；本票改整理路径的旋转（整理旋转归 T2，但须引用本票正向定义）。

## Answer

2026-09-21 用户五项全部定音。开图方向与整理方法票的「整理只走两个正向」不重审；两边共享产品边界，实现仍分家，不合成公开 seam。跨表面共享裁决已钉的契约 / 不改 `sendDragItem` / 不增强拖出到地面 / 画面类 Headless，本票不重开。本票不改 evaluator 代码。

冻结句：

> **BII 预放置始终使用绿/红半透明色块表达当前候选是否合法；框、图标与提交共享同一旋转结果。自动旋转保留边缘感应带和开阔中部防蠕动，只允许在两个可读正向之间切换，永不自动选择文字倒置的朝向。**

### Q1 — 半透明色块，可放绿不可放红

- 只要半透明色块，不要描边。色值冻结：绿 `(0.2, 1, 0.3, 0.85)`，红 `(1, 0.25, 0.2, 0.85)`。可放绝不是 BACKGROUND 深色。
- 可放置 = 绿；占用或越界 = 红。光标离开网格或预览无效时隐藏框。
- 互换占用仍红：当前候选本身不可直接放置；松手是否进入原版交换不改变预览语义。
- 原版深色框和未隐藏的 `dragItem` 幽灵不得盖住 BUE 框。玩家最终只看见这一套绿/红。凡 BII 已接管拖入的网格都画；不画地面投放。

### Q2 — 正向是拖入会话里的可读姿态

- 默认正向 = 原版拾取或进入拖拽时的基准姿态（通常数值 `rot=0`）。另一个正向 = 该基准再转 90°（通常 `rot=1`）。
- 不能机械把数值 0 当正向：若资产进包朝向不是 0，以进入拖拽时的原版基准为正向，再允许一次 90°。
- 自动旋转只在这两个可读正向之间切换。正方形不自动旋转。无论数值如何映射，自动旋转不能产生 180° 或 270° 倒置。文字、标识和图案必须保持可读。
- 整理路径引用同一产品定义（整理方法票已钉禁区）。

### Q3 — 倒置物品在自动旋转触发时拉回正向

- 当前处于倒置姿态且满足自动旋转条件时，拉回两个正向中能够合法放置的那一个：优先能放下且可读；两个都能放下则遵守感应带与进入姿态稳定规则；只有一个能放下则选它；两个都不能放下则红框，不伪造可放候选。
- 玩家手动按 R 仍可暂时转到倒置。自动旋转不得把倒置当成合法目标长期维持。

### Q4 — 框、图标、提交同一 rot

- 框宽高、图标朝向、松手提交共用最终旋转。禁止框按新朝向、图标按旧 `jar.rot`。禁止再叠一份旧朝向的原版幽灵。
- 横正向不是倒置。框与图标不一致、图标文字倒置、图标尺寸与 footprint 不一致，都是本阶段缺陷。

### Q5 — 感应带与 D2 保留，只收窄候选

- 边缘感应带、开阔中部保持当前方向、障碍边界引力全部保留。角落重叠区仍进入姿态优先。
- 自动旋转不再使用 `(currentRotation + 1) mod 4`。需要竖则选可读竖正向，需要横则选可读横正向；开阔中部当前正向能放下则保持。
- ADR 0003 决策正文不整篇重写；Consequences 记本票收窄。详细旋转规则以本票 + CONTEXT 为准。

### 本票不做

改提交权威；增强拖出到地面；管理面板色板；新 FeatureId；本票改整理求解器；另建描边层；用四向 +1 冒充两个正向。

受影响：CONTEXT「预放置框 / 默认正向 / 自动旋转」改为本票定音。ADR 0003 Consequences 追加收窄。玩家手册归文案票。SDK 零改。

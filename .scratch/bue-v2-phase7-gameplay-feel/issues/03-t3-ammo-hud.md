## Question

第五阶段 T7 / DEV-V5-06 把默认弹药 HUD 钉成：原版「当前 / 上限」保留，旁边追加「备匣 N · 备弹 M」。N = 身上五页匹配且有弹的备用匣本数（不含枪上那本、空匣、容器、地面）；M = 这些备用匣余弹 + 匹配弹药箱发数。刷新挂在 `UseableGun.updateInfo` 之后。用户开图裁定：备弹不够直接，弹药箱更新有延迟、要重新开关背包。

开图已钉（本票不重审公式方向）：

- 留原版「当前 / 上限」；
- 旁边一个数 = **总弹药** = 枪上匣当前发数 + 身上五页匹配匣发数 + 匹配箱发数；空匣贡献 0，不再单列备匣；
- 口径匹配继续跟现网压弹同一套；容器和地面不算；
- 触发面 = 枪上匣发数变化 **和** 身上五页匹配匣/箱数量变化（开火、换匣、原版换弹、拾取、丢弃、整理、压弹、合成）。

R2 是事实输入。本票裁产品语义与刷新合同，不在本票改投影代码。

1. **数字含义**：总弹药是否含枪上匣当前发数（开图原话含）？原版「当前」因此会与总弹药的一部分重复显示，玩家是否接受？无匹配弹药时显示 0 还是隐藏附加读数？
2. **文案**：废止「备匣 N · 备弹 M」。新标签写什么（「总弹药 {0}」/ 只写数字 / 其它）？是否仍追加在原版 infoBox 左列下半，不改枪模小字、不与尸潮条抢顶栏？

4. **Headless / 第三人称**：U3DS 不画是否沿用？第三人称枪模计数器动不动？
5. **与压弹/整理的关系**：被动压弹或整理改了匣/箱之后，总弹药是否走同一观察单源？禁止 HUD 与压弹用两套口径匹配。
6. **不做**：把容器/地面弹药算进总数；把总弹药做成新 FeatureId；改原版「当前/上限」含义；超限状态读数（超限仍范围外）。

## Answer

2026-09-21 用户六项全部定音。开图公式与触发面不重审。跨表面共享裁决已钉的契约 / FeatureId / 画面类 Headless / 文案不得先于行为，本票不重开。本票不改投影代码。被动压弹的触发与权威归被动压弹票。

冻结句：

> **持枪且更好的换弹体验运行时，原版「当前/上限」保持含义与字形；其下追加「总弹药 {0}」。总弹药 = 枪上匣当前发数 + 身上五页匹配匣发数 + 匹配箱发数。空匣贡献 0，0 也显示。枪上发数与原版 ammoLabel 同一事实源，身上五页与压弹同一匹配单源。开火或身上五页匹配弹药变化后不晚于下一帧更新，不得以开关背包或再开一枪当刷新。**

### Q1 — 两个数并存，重复是分层不是缺陷

- 原版「当前 / 上限」= 当前弹匣状态。总弹药 = 可持续射击资源。即使总弹药含枪上当前发数，也不合并、不覆盖。
- 无枪或无枪上匣：枪上贡献 0，不伪造一把枪。

### Q2 — 文案「总弹药 {0}」，0 也显示

- 废止「备匣 N · 备弹 M」，不再单列备匣本数当主读数。
- 持枪且功能运行时始终显示；总数为 0 时仍为「总弹药 0」。
- 位置沿用原版 `infoBox` 左列下半。不改枪模小字，不占尸潮 HUD。

### Q3 — 刷新不晚于下一帧

- 验收：打一发、拾取/丢弃/整理/压弹/合成导致身上五页匹配匣或箱 amount 变化，附加读数不晚于下一帧（宿主时钟同一拍或下一拍）。
- 授权 LIR 功能内部另挂观察缝（库存数量变化、枪上弹药变化）。不进公开契约，不另建第二套宿主泵。
- 重新打开背包不能作为刷新条件。只挂 `updateInfo` 不够，因为背包匣/箱变化默认走不到该 postfix。

### Q4 — 两份事实源，一套口径匹配

- 枪上当前发数与原版 `ammoLabel` 同一事实源。
- 身上五页弹匣与弹药箱继续复用压弹匹配单源（FillTargetItem / 口径谓词）。禁止 HUD 与压弹维护两套口径匹配逻辑。
- 不含容器与地面。

### Q5 — 切枪带走、停用回裸原版

- 第三人称枪模小字不改。
- 切枪、卸枪或信息框销毁时，总弹药行随原版 `infoBox` 一起销毁，不残留。
- 功能停用后立即回到裸原版「当前 / 上限」。
- U3DS 不画、不抛、不写客户端草稿。

### Q6 — 库存一变，HUD 跟上

整理、被动压弹或其它原版库存变化导致匹配弹药改变后，总弹药必须经同一观察单源在下一帧内更新。本票不裁被动压弹何时跑、怎么提交。

### 本票不做

容器/地面计入总数；新 FeatureId；改原版「当前/上限」含义；超限状态读数；用开关背包或再开火当刷新；第二套口径表；另建第二套宿主泵。

受影响：CONTEXT「总弹药」改为本票定音（文案、0 显示、下一帧合同、两份事实源）。玩家手册归文案票。SDK 零改。

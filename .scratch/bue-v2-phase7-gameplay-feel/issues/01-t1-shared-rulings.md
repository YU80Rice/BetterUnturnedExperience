## Answer

2026-09-21 用户六项全部定音（本节为冻结条目，T2..T8 直接引用）。开图已定的目的地、三块范围、不新增 FeatureId 不重开。治本边界（用户原话级）：本阶段只改三项官方功能的玩家体验和内部实现，不把玩法债务伪装成平台能力，也不通过 UI 投影掩盖主机权威未兑现。

### Q1 — 契约影响

- 新整理方法、总弹药 HUD、技能页模板、被动压弹、绿/红预放置框、正向旋转，全部落在官方功能 internal 或文档层。公开契约保持 **2.1 零扩面**；不把 2.2 当第七阶段入场券。
- `public` ≠ 契约原样沿用。本阶段没有触发 C.1 加性的共享需求。
- 6.5 挂起后的内部解释（五页同一套、值观察四字段、三条权威提交分家）本图当官方功能内部纪律引用，不兑现为公开 seam。

受影响：SDK 正文不因本阶段改版本账；CONTEXT「开发者契约」不改。

### Q2 — 官方先行消费与生态同权

- 官方先行消费维持：背包整理真实消费新整理方法；更好的换弹体验真实消费总弹药 HUD、技能页模板、被动压弹；更好的物品交互真实消费绿/红框与正向旋转。NoOpFixture 不替代。
- 生态**不同权到这些业务能力**：不把整理策略、换弹技能、BII 预览做成生态可登记的平台缝。面板上它们仍走现有设置/生命周期，不另开生态 API。
- 同权不等于同能力：契约面上的注册、生命周期、网络、设置规则仍官方/生态同一套。

### Q3 — 四条旧不变量全部授权重开

授权只解除旧不变量的禁止，**不等于批准新实现**。未裁出新边界前，现网与玩家手册仍按第五/四阶段正文。

1. 第五阶段唯一官方整理方法（行带排版 / `tagged-row-band-v1`）→ 新边界归整理方法票。
2. 技能 2 级 = 双击成功后再等 8 秒压一轮、枪须在手 → 新边界归被动压弹票。
3. 换弹技能按玩家×角色全局持久化 → 新边界归技能页/作用域票。
4. 自动旋转 = `(当前朝向+1) mod 4`（ADR 0003）→ 新边界归预放置框与正向旋转票。

ADR 0003 正文本票不改写；收窄后果由正向旋转票落进 ADR Consequences 或后继 ADR，不在本票预写旋转规则。

### Q4 — Headless / 无画面主机

- **画面类**（绿/红框、技能页、弹药 HUD、整理按钮外观）：U3DS 与无 Glazier 主机仍是不画、不抛、不写客户端草稿。
- **权威行为类**（被动压弹、整理提交、技能升级扣经验）：必须在 U3DS / P2P 主机上有正确权威行为，不能只靠「服务端没画面」或客户端投影蒙混。被动压弹即使枪不在手上，也必须由主机真实执行。

### Q5 — 文档与功能的关系

- 玩家手册是本阶段交付切片，不是可省的附件。
- **顺序约束**：文案不得先于行为裁决承诺尚未确定的机制。`CONTEXT.md` 由对应决策票定音时同步更新；玩家手册由文案票按最终裁决统一修改；SDK 本阶段不改。
- 第三方评审**不挡** `/to-spec`。实施交付仍必须经过既定双轴独立审查（这是实施纪律，不是本图规格出口门）。

### Q6 — 本阶段共享范围

**明确保留、不重开**：整理后合匣（功能 A）本阶段保留；不重开、不改其语义；不把它与 2 级被动压弹合并。

**冻结为范围外**（偷运须另开图）：新 FeatureId / 新官方功能模块；BueUi、面板选择器、i18n、统一色板；6.5 公开 seam、C.1 登记、DEV-V65-*；装备栏锁定；完整超限弹匣；工坊虚拟容器；拖放路径自动整理（更好的物品交互继续禁止在拖放时重排已占用格子）；第五阶段展望五项（工坊物品 ID、Xaero 式地图、Carry On、网格化放置、快捷栏手势）。

受影响：CONTEXT「整理策略 / 换弹技能 / 被动压弹 / 默认正向 / 自动旋转 / 总弹药」由开图意向改为本票授权重开；新边界句仍等 T2..T6，未裁出前现网正文有效。SDK 零改。Phase-5 已关闭地图不回写，以本图为准。

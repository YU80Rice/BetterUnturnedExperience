冻结句：

> **`StableLabelCompact` 是唯一官方整理方法：按固定玩家用途标签生成连续稳定名单，标签内按固有面积、最长边、短边和稳定键排序；从左上选择最靠上、最靠左且不制造内部空洞的位置放入，允许后一标签补前一标签的外边，但不得插入或拆散已完成标签区域。默认只使用两个正向，全部物品无法合法放置时零提交，剩余空位集中到右侧、下侧和右下。**

这不是行带排版的变体，不是智能整理，不是三种模式，不是全局最优装箱。

### Q1 — 20 档标签顺序整份沿用，行带放置整份废止

- 废止第五阶段「最左侧主体定行高、同标签从左到右填满再换行、不同标签可横向并排」的放入规则与行带评分。分类器与标签顺序**不重开**。
- 玩家用途标签顺序仍是：远程武器、弹匣、医疗用品、近战武器、投掷物、弹药、弹药箱、枪械配件、食物、饮水、工具、服装与防护装备、背包与容器、燃料、补给与制作材料、建造、设施与陷阱、地图与指南针、钥匙、其他。单源仍是内部 `PlayerUseLabel` 枚举序，不进玩家界面、不进契约。
- 分类失败进「其他」，不得因换算法丢物。弹药箱仍按给弹匣供弹的蓝图关系识别，不能只凭 SUPPLY。
- 内部实现标识 `StableLabelCompact`（implementation，不进玩家界面、不进公开契约）。不把 `tagged-row-band-v1` 永久伪装成新算法。

### Q2 — 不拆散 = 名单连续 + 空间四连通 + 关闭后冻结

机器判据（实施必须能红）：

1. **名单连续**：同一标签在稳定名单中必须连续，不能被其它标签穿插。名单键冻结为：标签序 → 固有占地面积（大到小）→ 固有最长边（大到小）→ 固有短边（大到小）→ 物品名称或物品 ID → 整理前从左上到右下的原顺序。面积与边长比较固有尺寸，旋转不改变排名。
2. **空间四连通**：同一标签的已占用格子必须四连通成一块区域。后一类不得填入该区域**内部被围住的洞**。补边只允许发生在前一标签区域的**外轮廓**或尚未被围住的连续空位上。
3. **标签关闭后冻结**：某标签全部物品完成放置后，后续标签不得重新安排、挤开或替换那些格子。已关闭标签不再回头修改。
4. **分散形状**：若某标签的物品天然由多个互不相邻的实例组成，判定的是该标签整体的已占用连通区域与内部洞，**不要求每个物品实例互相接触**。

阅读顺序连续（从上到下从左到右不得插入其它标签）**不是**硬约束——它与补边打架，不得拿来否决外轮廓贴边。

### Q3 — 内部空洞 vs 可用边缘

- 内部空洞 = 已被同类或已关闭区域包围、后来者填进去会把已完成区域切断的洞。
- 可用边缘 = 尚未被占用或围住的连续空位，包括大件旁边还没围住的格。
- 场景钉死：1×3 大件旁边尚未围住的空格，1×1 可以填。禁止的是插进已围住的洞。本方法不是「主体定行高、右侧空着」。

放入时按名单从前到后取物品，选择最靠上、最靠左、能够放下且不制造内部空洞的位置；默认 `rot=0`。

### Q4 — 整理只走两个正向

- 只允许 `rot=0` 与 `rot=1`。默认保持 `rot=0`；只有能明显减少内部空洞、补齐连续占用或避免合法物品无法放入时，才切到 `rot=1`。
- 同一物品 ID 尽量同一方向。永不由整理算法选择 `rot=2` 或 `rot=3`。文字、标识和图案必须保持可读。
- 与更好的物品交互的默认正向共享**产品边界**，各自保留内部实现，不合并成新的公开 seam。正向的资产级精确定义仍归预放置框与正向旋转票；该票若收窄定义，整理跟同一套。
- 「明显减少」落实为内部评分，本票钉禁区不钉分值。

### Q5 — 凡背包整理都走同一模块

当前栏、全身、容器整理、入包失败恢复、快速转移失败后的接收侧整理，只要执行的是背包整理，就必须调用同一个 `StableLabelCompact` 模块。各入口只负责触发、范围、权限、会话和原版提交，不得复制标签排序、放置、旋转或失败验证。快速转移源页的恒等离场仍属恢复事务，不是排版，保持原样。

### Q6 — 全部放下才提交

硬性沿用第五阶段第一层：全部可放置物品都放下或明确失败；不重叠、不越界、不丢物、不重复使用同一件；相同输入相同输出；失败零提交。不为整洁而漏放。

- 成功表面句（文案票采用）：「背包已整理：同类已归拢，并从左上紧凑排列。」
- 失败沿用明确原因分类，**禁止**写「已经整理但仍有 N 件无法放入」。无法放下的件数只能作诊断或失败详情，不能描述成部分成功。

结构层改用本方法优先级，不再用行带评分：全部放下 → 名单按标签分段且同标签连续 → 标签内大件优先且同 ID 归拢 → 已占用内部空洞最少（理想为零）→ 从左上紧凑、行内不夹内部空洞 → 空闲尽量一块并靠右下 → 后一类只补外边不拆已完成区域 → 同 ID 尽量相邻 → 默认正向、同类方向统一 → 少旋转、少无意义移动 → 完全相同保留整理前顺序。

### Q7 — 退役 direction 对算法的影响

- 不新增玩家可选策略，不给第三方加载，不保留行带与新方法并行。
- `inventorytidy.direction` 不再影响整理结果。完全相同条件下固定保留整理前从左上到右下的顺序。
- 旧 `mode` / `direction` 值仍可读取以免旧存档解析失败，但不再决定算法。管理面板不再把 direction 当作有效算法设置。标题栏仍只留「整理」，不暴露 `StableLabelCompact` 名称。

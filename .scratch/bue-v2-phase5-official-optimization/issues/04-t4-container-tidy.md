## Question

用户本阶段要求「给容器加整理按键」。Phase-4 把「不注入 STORAGE」写成永久产品不变量；原 LaunchInventoryTidy v1.0 曾给 STORAGE 画过按钮，但整理执行从不包含 page 7，v2.0.1 因「可点但服务端拒」拆掉。BUE 现网 `HEADER_INJECT_COUNT = 5`，仓储栏无按钮。

须 T1 先授权重开不变量。本票在授权前提下裁新边界：

1. **「容器」是谁**：只 STORAGE（箱子/车辆后备箱，U3-SDK 页 7）？含其他可打开网格？尸体 AREA、装备槽 0/1 是否永远排除（预期排除）？
2. **按钮表面**：是否仍走标题栏「整理」、尺寸是否沿用 60×60 @ -130 还是容器页另算避让？Ctrl+左键全身整理是否**绝不**含容器（玩家手册现行「不含仓储栏」）？
3. **权威**：整理请求是否走现有 LIT 跨端通道、由服务端权威提交？多人同时开同一容器怎么处理（拒 / 锁 / 只整理自己看到的快照）？
4. **失败可见**：若服务端仍会拒（虚拟工坊容器、无权限、容器已关），按钮是不画、画了点了说原因、还是画了当空操作？禁止再做「可点但静默失败」。
5. **与锁定/被动**：容器页要不要锁定？被动整理要不要对容器 `tryAddItem` 生效（建议本票只表态，细节归 T5/T6）？
6. **Headless / 主机**：U3DS 与 P2P 主机无本地 Glazier 时，远程客户端打开容器是否仍能看到按钮、请求是否仍由主机执行？

未获 T1 授权则本票答案必须是：容器整理移出本阶段，或只做非 STORAGE 方案并写明为何不算重开。R3 是事实输入。

## Answer

2026-09-14 用户修订原推荐后定音。跨表面共享裁决已授权重开「不注入 STORAGE」，并要求单独定义权限/生命周期/关箱并发；整理排序票已要求凡背包整理入口消费统一排版模块。本票不重开那些条目，不写生产代码。

架构冻结：第 7 页只是原版当前挂载位置，**不是**容器整理模块的身份。禁止 `if (page == 7) tidy(items[7])` 当产品语义。内部形状：

```
容器表面适配器 → 当前容器会话事实 → 容器整理请求
  → 统一标签分段行带排版 → 服务器权威校验与提交
```

请求至少绑定容器种类、容器会话身份、请求者身份、容器版本/指纹。标题栏补丁只画按钮；识别、权限、生命周期、提交集中在背包整理内部的容器整理能力（不是新 FeatureId）。

### Q1 — 本阶段两类原版容器

第五阶段只支持：玩家当前合法打开的普通世界容器，以及当前玩家已获授权访问的车辆后备箱。工坊虚拟容器、地面物品页、主副手槽、装备槽页不在本阶段。

箱子与后备箱**不是**同一种容器。它们共用整理能力，但必须各有适配器（世界容器 / 车辆后备箱），分别处理单 opener、距离、锁、关箱，以及驾驶座授权、离座、换座、车辆状态。调用方只问「当前容器能否整理」。

工坊虚拟容器：能力投影 `Unsupported`，不画按钮，留下可诊断原因；以后有可靠适配器再单独立票。不因「现在没有识别字段」写成永远不能支持。

### Q2 — 按钮与全身整理

容器打开且能力为可用时，在**当前容器标题栏**显示「整理」；点击只整理当前打开的这一份容器网格。文字仍叫「整理」，不叫「整理箱子/后备箱」。布局由容器标题栏适配器提供，**不**复用服装页固定 -130。

三条硬规则：当前栏按钮 → 当前玩家页；Ctrl+整理 → 玩家身上五页；容器按钮 → 当前打开容器。Ctrl+左键全身整理永远不含容器，不受「此刻是否开着箱子」影响。不做「整理附近所有箱子」。

### Q3 — 谁可请求、并发与版本

只有当前合法打开者可以请求。服务器提交前重新验证：会话仍在、请求者仍有权、容器身份未变、物品版本/指纹未变，再调用统一排版、完整验证、原子提交、广播新状态。验证失败或版本变化 → 零修改。

普通箱子与后备箱继续用原版访问控制（opener/忙碌；驾驶座授权），**不**另造 BUE 整理锁。请求期间他人合法改了容器内容 → 明确过期拒绝，不覆盖、不静默重读再排一次。

### Q4 — 何时画按钮、失败怎么说

按钮可见 = 能力投影「可用」，**不是**授权承诺。投影至少包括：容器类型、会话有效、当前玩家有整理权限、背包整理正在运行、该类型有适配器、标题栏仍在。不支持、虚拟无适配器、无权限、会话未建立、功能未运行、U3DS 进程自身无客户端 UI → 不画。

点下去之后服务器仍必须再验。关箱、离座、丢驾驶座、插件关闭、内容已变、功能被停、会话换代 → 结构化失败，中文原因至少能区分：容器已关闭；已失去权限；内容已变化请重新整理；当前类型不支持；排版失败未改物品；整理功能当前不可用。禁止可点但静默没动静。不要只拿一个笼统「未改动」给玩家看。

U3DS 进程不构造 Glazier、不画按钮；连到 U3DS 的客户端打开受支持容器时可以画；请求由主机权威执行，不能因服务端没 UI 就改成客户端本地挪格子。

### Q5 — 容器不锁、不做容器被动整理

本阶段容器页不画锁定，也不启用容器被动整理。锁定票、被动整理票各自裁决，且不得复制排版算法。容器本就不进全身整理，所以「跳过某页」的锁定没有对象；防掉落是另一套交互保护。被动整理默认仍只对玩家身上页。

新 FeatureId；把页上限改成 7 当完成；BUE 整理锁替代原版开箱规则；全身整理卷进当前箱子；可点但静默失败；本阶段支持虚拟容器/地面摊/装备槽；在本票改生产代码。

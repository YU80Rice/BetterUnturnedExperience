## Question

O-LIT-1 自 DEV-V2-08 起挂账：玩家认为排列算法质量差，「后续再说」。现行 `default-grid-v1` 按迁入勘误口径原样冻结；面板只有同类/空间/大件 × 降序/升序，没有策略选择器。用户本阶段要求「整理背包的排序方式需要优化」。

本票裁决产品语义，不在本票改求解器：

1. **改什么**：换排序规则（物品进入计划的先后与分组），还是连放置规则（网格占位与旋转）一起改？CONTEXT「整理策略」禁止在纳入阶段同时换两套——纳入已结束，本阶段是否允许动放置？
2. **怎么交付**：改 `default-grid-v1` 内部行为（旧计划不再字节级复现），还是新增第二条策略并保留旧策略？要不要策略选择器（Phase-2 明确不做）？
3. **三种模式的去留**：同类/空间/大件是否仍是玩家能懂的三档？若算法变了，档位名与描述是否重写（现文案「不承诺排序算法或 O-LIT-1」）？
4. **成功标准**：玩家可观察的「更好」是什么（同类更紧、大空位更完整、武器弹药相邻、少碎洞）？用哪些失败案例当验收（O-LIT-1 原观察若能找回）？
5. **谁消费**：当前栏整理、全身整理、（若 T4/T5 批准）容器整理与被动整理是否共用同一套排序？
6. **不做**：第三方动态加载策略、把排序做成独立官方功能、在本票写求解器代码。

R2 报告是事实输入。O-LIT-1 勘误口径本票有权废止或收窄，须显式写进裁决。

## Answer

2026-09-14 用户提出统一标签分段、行带式矩形排版，并修订本票原 Q1「只改排序」推荐。本节为冻结条目。本票不写求解器代码。跨表面共享裁决已钉：不新增 FeatureId、生态不接整理策略、契约 2.1；本票不重开。

产品定义（冻结）：

> 物品按照固定的玩家用途标签顺序，从左上向右下进行分段排列。每个标签形成连续的紧凑区域；区域内部以最左侧主体物品确定行带高度，同标签物品优先从左到右填满当前行带，无法继续规整放置时再换到下一行。不同标签可以横向并排，但必须形成清晰、整体单调的边界；否则新标签从下一行最左侧开始。剩余空间集中到右下，并尽量保持为少量宽而完整、可继续利用的区域。

这是**唯一官方整理方法**，不是三种模式之上的第四档。视觉取向改写为：在所有满足完整放置和合法性的布局中，优先选择视觉结构更整洁的布局；不为了视觉整洁而丢弃可放置物品，也不为了多填一格而破坏标签连续性。

### Q1 — 允许同时重写排序和放置

- 废止 O-LIT-1 / 纳入阶段「排序与放置都不改」以及本票开问时「只改排序、放置原样」的推荐。本阶段**同时重写排序和放置**，但只围绕标签分段、行带排版、右下留空；**不做**数学意义上的全局最优装箱器。
- 硬性底线先于视觉：不重叠、不越界、不丢物、能放下时必须给出合法布局、失败不得提交半成品。
- 求解器对外仍是一个深模块：输入 = 物品集合 + 网格尺寸 + 少量稳定偏好；输出 = 确定性布局计划或明确失败。分类、标签序、主体、行带、并排、旋转、右下评分、稳定收尾、合法性验证全部留在模块内部，不暴露给当前栏 / 全身 / 容器 / 被动整理入口。

### Q2 — 唯一算法，无玩家选择器

- 不新增玩家可选策略，不给第三方加载，不保留三套并行实现。
- 内部实现标识建议 `tagged-row-band-v1`（implementation，不进玩家界面、不进公开契约）。
- 不把旧名 `default-grid-v1` 永久伪装成新算法。旧 `inventorytidy.mode`（同类 / 空间 / 大件）与 `inventorytidy.direction`（降序 / 升序）**仍可读取**，但不再决定算法；首次读取归一到统一排版并随后保存为新规范值。升序 / 降序若仍存在，最多影响完全相同条件下的稳定收尾，不得改变标签顺序和主要排版。
- 标题栏继续只留「整理」。不要让玩家选择「行带式矩形排版」。

### Q3 — 三档从玩家界面移除

- 「同类 / 空间 / 大件」不再作为玩家档位或三套语义。旧值只做存盘兼容与迁移说明。
- 不把 `tagged-row-band` 暴露给玩家。必要时内部可有「整理偏好：标准」，本阶段不增加第二套玩家算法档。
- 面板描述句（Q61 三档文案）随档位退役；玩家手册相应改写。循环切换控件仍可用于其它 Choice，只是 LIT 这两条不再是算法开关。

### Q4 — 成功标准三层，不继承旧坐标

不要求旧布局字节级复现。O-LIT-1 原观察无物品清单，不能当黄金案例。

1. **硬性（机器）**：全部放置或明确失败；不重叠、不越界、不丢物、不重复使用同一件；旋转后宽高正确；相同输入相同输出；失败零提交。
2. **结构（尽量机器化，用评分表达「尽量」）**：标签顺序固定；不同标签不穿插；同标签连续成块（网格太窄除外）；标签切换只在允许的行带或列段；不回头填已跳过的洞；新标签默认从下一条可用行带左侧开始；空区评分偏向右下连续空区；同一物品 ID 在同标签内尽量连续，但不要求每个 ID 独占矩形。
3. **视觉（评分 + 实机目视）**：大件作左侧主体；同类方向尽量统一；默认正向（文字/标识正常可读，不为整理把「步枪」变成倒置「枪步」）；少旋转、少移动；避免细长件造成难看断裂。不承诺唯一布局，但无关小变化不得大幅跳版。

至少准备这些输入类型：同 ID 医疗堆；同标签大件/小件/细长混放；可横向并排的多标签；右侧放不下必须换行；有旋转才能放下；不旋转也能放下但旋转更差；落入「其他」；弹药箱 vs 普通 SUPPLY；「放得下却重叠失败」不得再出现。

旋转：图标与占位绑定，旋转即转图标。仅当整体版面明显改善、避免漏放或消除死洞时才允许，并尽量整组统一方向。默认正向优先。

### Q5 — 凡「背包整理」都走同一模块

当前栏、全身整理，以及日后获批的容器整理和被动整理，只要执行的是背包整理，就必须调用同一个统一排版模块。各入口只负责触发、范围和权限，不得复制算法。本票**不**替容器票或被动整理票决定它们是否启用。

### 四条必须写入实施规格的技术裁决

1. **玩家用途标签分类器**是统一排版模块的内部缝（`Item → PlayerUseLabel`），不是公开契约。同一物品在相同资料下标签稳定；`GUN` / `MELEE` / `MEDICAL` 等明确类型优先；弹匣不能把所有 `MAGAZINE` 无条件当可用弹匣；弹药箱按 `FillTargetItem` 为弹匣供弹的蓝图关系识别，不能仅凭 `SUPPLY`；材料与任务物品无可靠类型则进「其他」；分类失败不得导致物品消失。标签顺序冻结为：远程武器、弹匣、医疗用品、近战武器、投掷物、弹药、弹药箱、枪械配件、食物、饮水、工具、服装与防护装备、背包与容器、燃料、补给与制作材料、建造、设施与陷阱、地图与指南针、钥匙、其他。这是玩家用途标签，不是 `EItemType` 枚举序。
2. **横向并排必须可计算**：列段起点、右侧何时可放下一标签、剩余宽度不足何时换行、标签区域可否被后续标签再填、何为死洞、高度是否允许不同。不允许把「边界清晰」留给实现者感觉。
3. **主体选择不能只按高度**：候选按对当前标签区域的贡献估算，排除会制造明显狭长空洞的细长高件，再按高度、面积、长边、宽度、稳定顺序收尾。「改善整体版面」落实为内部评分。
4. **失败是事务性的**：`TryPlanLayout(items, grid) → Success(plan) | Failure(reason)`。规划不改真实背包；计划通过完整验证后外层才提交。

### 本票不做

第三方动态加载策略；把排版做成新官方功能 / 新 FeatureId；本票改生产求解器；全局最优装箱；为整洁而丢可放置物品；把内部步骤暴露成多个入口各自实现。

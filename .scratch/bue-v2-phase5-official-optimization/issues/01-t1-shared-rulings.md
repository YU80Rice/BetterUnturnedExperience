2. **官方先行消费**：本阶段优化是否仍要求官方功能真实消费（LIT 吃排序/容器/被动/锁定，LIR 吃技能/HUD），NoOp 不替代？生态功能要不要同权接到锁定或整理策略？

4. **Headless**：U3DS 无 Glazier。容器按键、锁定、弹药 HUD 的服务端验收是否仍只要求不画、不抛、不写客户端草稿？被动整理若在服务端权威页上触发，是否必须在 U3DS 有权威行为而不仅是「不画」？
5. **文档与功能的关系**：开发手册（T2）是本阶段交付切片的一部分，还是只服务后续实施？第三方评审是 T2 的出门条件，还是 T8 闭包之后由用户另做、不挡 `/to-spec`？
6. **本阶段不做清单（共享）**：新 FeatureId、BueUi、选择器、i18n、第六阶段五项、把被动整理做成更好的物品交互——从共享规则再钉一次，避免后续票偷运。

每项输出：裁决条目 + 受影响的 CONTEXT.md / SDK / Phase-4 地图不变量（如需修订）。

## Answer

2026-09-14 用户六项裁决全部定音（本节为冻结条目，T2..T8 直接引用）。开图已定的目的地、六块范围、不新增 FeatureId 不重开。

### Q1 — 契约影响

- 本阶段六块（排序、容器按键、被动整理、锁定、换弹技能/弹药 HUD、给人看的开发手册）全部落在官方功能 internal 或文档层。公开契约保持 **2.1 零扩面**；不把 2.2 当第五阶段入场券。
- 开发手册不是契约，不得与 SDK 抢权威。`public` ≠ 契约的纪律原样沿用。
- 若未来某条必须给生态用，另开 Minor 2.2，不在本阶段偷渡。本票 Q2 已否决「生态登记锁定 / 整理策略 / 换弹技能」，因此本阶段没有触发 2.2 的共享需求。

受影响：SDK 正文不因本阶段改版本账；CONTEXT 开发者契约条目不改。

### Q2 — 官方先行消费与生态同权口径

- 官方先行消费维持：背包整理真实消费排序、容器按键、被动整理、锁定；更好的换弹体验真实消费技能与弹药 HUD。NoOpFixture 不替代。
- 用户原话：这些是官方功能的优化；第三方与 BUE 接触的只有「前置库和运行平台」。因此本阶段**不同权到业务能力**：不把锁定、被动整理、整理策略、换弹技能做成生态可登记的平台缝。面板上它们仍走现有设置/生命周期，不另开生态 API。
- 同权不等于同能力：契约面上的注册、生命周期、网络、设置规则仍官方/生态同一套；整理算法与换弹技能仍是官方功能的业务能力。

### Q3 — STORAGE 永久不变量重开授权

- **授权**后面的容器整理按键票重开 Phase-4「不注入 STORAGE」这条不变量。
- 用户原话：之前是因为容器整理有 bug 才关的，现在重启。授权 ≠ 已经批准注入；新边界（哪些容器、权限、生命周期、关箱并发、失败必须可见）由该票裁。未裁出新边界前，现网与玩家手册仍是「不含仓储栏」。
- 研究报告已标明：不能只把页上限改成 7。本授权包含「必须单独定义权限/生命周期/关箱并发」，细节不在本票展开。

受影响：CONTEXT「整理按钮」继续写「仓储栏是否注入由第五阶段重开裁决」；Phase-4 地图该条永久不变量以本图为准被授权重开，不回写已关闭的第四阶段地图正文。

### Q4 — Headless / 无画面主机验收分工

- **画面类**（整理/锁定按钮、弹药 HUD）：U3DS 与无 Glazier 主机仍是不画、不抛、不写客户端草稿。
- **权威行为类**（被动整理、容器整理请求）：必须在 U3DS / P2P 主机上有正确权威行为，不能只靠「服务端没画面」蒙混。page=7 协议与 `tryAddItem` 挂哪侧归后续票。

### Q5 — 文档与功能的关系、第三方评审

- 给人看的开发手册是本阶段交付切片，不是可省的附件。
- 用户原话顺序：**先重写手册 → 用户请第三方评审 →「前置库和运行平台」这一段结束 → 再实施官方功能优化。**
- 第三方评审**不挡**本图 `/to-spec` 闭包，也不是 FeatureId、不进公开契约。评审对象与材料清单由手册票钉；本票只钉顺序和「不挡规格出口」。

### Q6 — 本阶段共享不做清单

冻结为：新 FeatureId；BueUi；物品/配方/生物可视化选择器；面板 i18n；统一色板；路径调试；第六阶段五项；把被动整理做成更好的物品交互的一部分。

「更好的物品交互」禁止的自动整理 = 拖放路径上不得重排已占用格子、不得整页整理、不得合并堆叠。被动整理仍属背包整理，只在原版入包失败时整页重排，**不挂到拖放预览上**。用户确认维持这条冻结；若要把「拖到放不下就整页整理」做进更好的物品交互，须另开图改该功能禁令，不在本阶段偷运。

受影响：CONTEXT「被动整理」避免项保持「自动整理、更好的物品交互的拖放增强」。

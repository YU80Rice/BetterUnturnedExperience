## Question

用户把三级超限收成三分支，请对照 R6/R7 与现网 LIR 压弹，判断第五阶段能否安全做：

1. 当前匣 `amount == 0` 且后备够把这本匣填到 `MaxAmount` → 先跑现网式压弹（先箱后备用匣）填满枪上匣 → 再进入 R7 那种限时冻匣窗口（期间不减当前匣；结束按窗口内打出的发数从箱+备用匣折算）。
2. 当前匣 `amount > 0` → 不先压，直接进同一窗口。
3. 当前匣空且后备不够填满 → 不激活，提示「无后备弹药」。

对照 U3-SDK / 现网 `TryRepackTransactional` / R7 报告，写出 `.scratch/bue-v2-phase5-official-optimization/research/2026-09-14-V5-R8-overlimit-prime-then-burst.md`。

必须回答：

1. 现网压弹能否只填**枪上那一本**（装备槽 `state[10]` / 当前匣 jar），还是只会填背包页 2..6 里的未满匣、不管枪上？若不能填枪上匣，分支 1 在现网压弹上是否直接失败？
2. 填满成功后 `ammo` / `state[10]` 是否已经 `>= ammoPerShot`，从而满足 R7「有弹才激活冻匣」的前提？
3. 两笔账会不会打结：第一笔压弹已经扣了箱；窗口结束第二笔再按开火发数扣箱。是否必须在激活时快照「压弹后剩余后备」作为窗口上限？
4. 分支 2 后备为 0 时：结束不扣、只默认冷却，是否还触发 R7 的漏结算免费伤（窗口内冻匣等于没为伤害付钱——因为当前匣本就不减）？这是产品可接受还是必须禁止「有弹+零后备」开窗？
5. 结论：可安全做（列出必做步骤）/ 仅当禁止某分支时才可做 / 与 R7 同级缺陷不可做。

只查证不改码。R7 结论是输入。

## Answer

2026-09-14：**与 R7 同级缺陷不可做**（same-as-R7-unsafe）。现网 `TryRepackTransactional` 只扫页 2..6、只填背包未满匣 `jar.item.amount`，不写枪上匣 / `UseableGun.ammo` / `state[10]`；分支 1 字面复用现网压弹直接失败，空匣仍不满足 R7 有弹准入。真填枪上匣 = T7 禁止的激活合并，且压弹扣箱与窗口结束再扣会打成两笔账（cap 必须钉压弹后剩余，也救不了现网路径）。分支 2 零后备开窗 = 冻匣免费伤，必须禁止，默认冷却不能买单。禁止分支 1 只是退回 R7 有缺陷近似，不构成本票可安全做。

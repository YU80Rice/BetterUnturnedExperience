## Answer

2026-09-14 用户修订原推荐后定音（本节为冻结条目。跨表面共享裁决已钉：手册不是契约、先写手册再外请评审、不挡 `/to-spec`；本票不重开那些条目）。本票只裁分层、形态、落点、覆盖面与评审包，不写手册正文。

### Q1 — 四层冻结，不新增第五层

- **玩家手册**：人，安装升级故障。文件保持 `docs/BetterUnturnedExperience-Player-Handbook.md`。不与开发者入口合并。
- **SDK**：生态作者的契约唯一事实源，目录保持 `docs/sdk/`，继续「不设第二契约目录」。给人看的开发手册可以解释 SDK，**不得重新定义、不得全文复制**。删除测试：删掉开发手册后，契约细节仍须能从 SDK + NoOp 找回；删掉 SDK 后，手册不得假装承担全部契约。
- **给人看的开发手册**：人（贡献者 + 第一次写生态插件的作者）。专门目录 `docs/developer/` 是这一层的入口，不是新的文档层。内部可有总览图、模块结构、最小接入范例，仍共同属于这一个人类开发者入口。
- **给 AI 的执行规格**：继续用阶段 `spec.md` + 票面，不另产 agent 手册。不把阶段规格改写成给人看的手册。

`CONTEXT.md` 只当词汇表，`AGENTS.md` 只当 agent 操作规则。权威关系：注册与运行平台能力以 SDK 为准；模块在生态中如何定位和存活由开发手册解释；最小可运行实现以 NoOp 为准；阶段为什么这样设计由 `.scratch` 规格与票面负责。

### Q2 — 形态：一张总图 + 三个短章

「一图流」升级为：

1. **一张总图**：BUE 模块生命周期与生态接入（职责结构和生命周期结构，不是类图/文件树）。
2. **短章一 · 模块结构**：主 DLL 内官方源码模块 vs 前置库和运行平台 vs 第三方从哪个缝接入；何时注册、何时获得平台能力、何时退出。
3. **短章二 · 最小接入流程**：三到六步方向 + 链到 SDK，不复制字段表和码表。
4. **短章三 · NoOp 范例导读**：先看哪个文件、注册缝、生命周期入口、平台能力消费、哪些是必要代码、哪些是测试辅助。不把 NoOp 全文贴进手册。

禁止写入给人看的正文：码表、版本账、诊断码全表、决策过程、阶段票号、`.scratch` 规格、AGENTS.md、架构双语长文、官方业务实现细节（排序算法、被动整理规则、锁定、换弹技能）。

### Q3 — 落点：专门目录，不当第二份 SDK

```
docs/
├── BetterUnturnedExperience-Player-Handbook.md
├── developer/
│   ├── README.md
│   └── BetterUnturnedExperience-Developer-Handbook.md
└── sdk/
    └── BetterUnturnedExperience-SDK-Assembly-Identity.md
```

- 不进 `docs/sdk/`。玩家手册与开发者手册并列但分开。
- README「给生态开发者」改成：先链 `docs/developer/` 入口，再链 SDK 与 NoOp。
- **范例来源唯一**：可运行实现只在现有 `src/BetterUnturnedExperience.NoOpFixture/`。手册第三短章导读它。若另建 `docs/developer/examples/` 导读页，也只能解释 NoOp，禁止复制第二套接入代码。
- 本阶段给会抢权威的 `.scratch` 长文加 SUPERSEDED / 「历史资料，不是现行契约」标（至少 V1 双语规格、共享契约草案、生命周期隔离稿、开放运行时提案），指向 SDK + 新手册；**不删文件**。

### Q4 — 覆盖面：前置库和运行平台 + 一个最小范例

**主体（生态可接入）**：运行时注册、前置库和运行平台、`IFeatureBootstrap` 能力、NoOp 生态模块、生命周期与退出。说明责任、接入缝、生命周期、第三方必须做 / 不准做。

**官方业务模块只结构性点名**：更好的物品交互、背包整理、更好的换弹体验、更好的尸潮播报位于主 DLL 内部，**不是**第三方要注册或实现的模块。不写其业务规格。不预留第六阶段空槽。

范例地位：SDK 定义必须符合什么；NoOp 展示最小实现；手册解释为什么这样接、先看哪里。范例须带声明：「用于展示最小接入路径，不扩展 SDK 契约；与 SDK 不一致时以 SDK 为准。」最小范例只演示成功注册、读取必要平台能力、一次启动与退出；不掺真实业务。

### Q5 — 评审包与「手册稳定」

- 评审对象：`docs/developer/` 下的开发者手册、该目录入口页、README 中的开发者入口。SDK 作为被引用契约来源，不整本重审。AI 执行规格不进评审包。
- 「稳定」= 本票形态冻结 + 实施票写出该目录 + 用户目视过可以外发。人选和邀请由用户做。
- 跨表面共享裁决的顺序维持：先写手册 → 用户外请评审 → 「前置库和运行平台」这一段结束 → 再实施官方功能优化。评审仍不挡本图 `/to-spec`。

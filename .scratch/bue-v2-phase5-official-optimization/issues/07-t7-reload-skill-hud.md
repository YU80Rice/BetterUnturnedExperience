## Question

用户原话拆成两层，须分开裁，避免把「默认就有的 HUD」和「要升级才有的双击 R」揉成一个开关：

**默认（更好的换弹体验启用即有，不耗经验）**：在原版弹药显示旁边显示背包内还有多少个**有子弹的弹匣**，以及**总后备弹药数量**。原版 `UseableGun.updateInfo` 只画「弹匣内数量 / 弹匣弹药上限」。

**技能（耗经验升级，三级）**：
1. 一级：激活双击 R 一键压弹（现网 0.3s 窗口、合并同 ID 弹匣 + 弹药箱填弹——即今天的功能 B）；
2. 二级：在一级手动激活基础上，等待一段时间后自动压子弹；
3. 三级：超限弹匣——双击 R 后优先消耗背包内对应口径弹药箱，再消耗弹匣子弹。

现网已经有与「二级」易混的能力：**整理后自动压弹**（功能 A，`TidyCompleted` → `AutoReloadAfterTidyAction`，同步、只合并同 ID 弹匣、不填弹药箱、无等待）。BUE 无自建经验/技能树；原版有 `PlayerSkills` 经验与 OFFENSE/DEFENSE/SUPPORT 技能。

本票裁决：

1. **默认 HUD**：数字含义（「有子弹的弹匣」是否含当前装上那本、是否含空匣、总后备是否含弹药箱 + 其它弹匣余弹）？画在 `ammoLabel` 旁还是另起标签？原版格式是否保持、只追加？U3DS/第三人称枪模计数器动不动？
2. **技能进度存在哪**：挂原版经验（`PlayerSkills.experience` / `askSpend`），还是 BUE 自建与原版经济隔离的进度？挂原版哪条技能槽，还是管理面板里 LIR 自己的三级？无经验的单人/未开启经验服务器怎么处理？
3. **一级与现网双击 R**：现网双击 R 是默认能力。本阶段是否改成「未升一级 = 只有 HUD + 原版单击 R，双击 R 失效」？这是对现有玩家的行为收紧，必须显式批准。
4. **二级 ≠ 整理后自动压弹**：二级的「等待一段时间后自动压」触发源是什么（换弹结束、弹匣不满、开火消耗）？与功能 A 是并存、取代、还是功能 A 保持且二级是另一条？等待是固定秒还是可设？
5. **三级超限弹匣**：现网功能 B 已经会从弹药箱填弹。三级是改优先级（先箱后匣），还是允许把弹匣压到超过 `MaxAmount`？「超限」二字必须定义，不能留作文案。
6. **官方功能边界**：全部留在更好的换弹体验内，不新 FeatureId。技能描述走 LIT/LIR 设置页还是独立技能 UI（预期不建技能树 GUI，用设置或原版技能面板）？

R5 是事实输入。不做：新官方功能「技能系统」；把尸潮 HUD 的 LHT 补丁当弹药 HUD 先例就照搬坐标。

## Answer

2026-09-14 用户修订后定音。废止开问时「三级=压过 MaxAmount」的推荐。被动整理成功不发 `TidyCompleted` 已钉死，本票不重开。契约仍 2.1，不新 FeatureId。

产品拆三层，不得混进一个设置字段：玩家进度（等级）、功能运行状态（冷却/等待/超限会话）、HUD 投影。

### Q1 — 默认弹药 HUD

更好的换弹体验启用即有，不耗经验。原版 `当前 / 弹匣容量` 保留含义。旁边追加：

- **有弹匣 N**：身上五页、与当前武器口径匹配、`amount > 0` 的备用弹匣本数。不含枪上那本、空匣、容器、地面。
- **后备弹药 M**：这些备用匣余弹 + 能经 `FillTargetItem` 给当前匣供弹的弹药箱发数，匹配规则与现网 LIR 一致。不含容器、地面、不匹配箱。

只扩展原版弹药信息区（右下 `infoBox` 一带）。不改枪模小字。不与尸潮条抢顶栏。U3DS 不画。HUD 不因等级隐藏普通弹药。超限激活时必须额外显示明确状态（例如「超限弹匣：已激活」）。

### Q2 — 等级在 U 菜单战斗区下方，不占原版槽

视觉：原版 U 技能菜单「战斗」最下面追加 BUE 换弹技能分区。事实：等级由 LIR 自己按玩家/角色持久化，**不**写入原版 `Skill[][]`。升级花原版经验，主机检查余额后 `askSpend`（或等价权威扣减）；客户端只显示主机确认的等级。新档不送等级。不造第二套经验。

等级模型：

| 级 | 名称意向 | 双击 R | 额外技能冷却 | 后台自动压弹 | 超限弹匣 |
|---|---|---|---|---|---|
| 0 | 基础 | 保留现网 | 有，较长 | 无 | 无 |
| 1 | 快速换弹 | 保留 | 取消额外技能冷却，**保留技术安全闸** | 无 | 无 |
| 2 | 自动压弹 | 保留 | 同 1 | 有 | 无 |
| 3 | 超限弹匣 | 保留 | 同 1 | 有 | 可激活 |

具体每级经验、0 级冷却秒数：**本票不钉**，留给实施规格或后续数值票。U 菜单追加区须在实施前验证原版技能页构造/刷新、单人与 P2P 差异；那是实施风险，不挡本票产品裁决。

### Q3 — 0 级仍能双击；「取消 CD」不是取消技术闸

现网双击 R 不锁进一级。最终可用时间 = 技术安全闸（现网约 1.5s 防重复提交，一级也不得删）+ 技能等级对应的额外冷却。不要把 0 级叫「自动压弹冷却」（0 级没有后台自动压弹），正式名称：**技能冷却**或**双击换弹技能冷却**。冷却中再双击：红色「换弹技能冷却中：还需 X 秒」，剩余时间以主机为准。技术闸触发不要伪装成技能冷却，除非它就是技能冷却。

### Q4 — 二级 ≠ 整理后合匣

功能 A 保留：玩家点「整理」成功 → `TidyCompleted` → 同 ID 匣合并，不填箱。被动/快速转移恢复仍不触发。

二级：双击 R **成功**后进入固定等待（建议 8s，本阶段不可设）→ 条件仍满足则再自动压一轮（弹药箱填匣，不拆别的匣）。执行前重检：仍是同一把枪、同一匣、可换弹、未死未切枪、仍有匹配弹药、等级仍允许、无进行中事务、未因失败/冷却卡住。不满足则取消，不强制操作。手动再双击仍走手动，吃技术闸与技能冷却。

### Q5 — 超限 = 临时供弹会话，不是超容

废止「MaxAmount + 一半」。三级双击 R 激活临时持续供弹：先消耗匹配弹药箱，再消耗备用匣余弹；**当前装上的匣不当备用源，激活瞬间不清空它**。不把 amount 写成无限，不把箱和匣合并进当前匣。内部应是供弹会话：主机按每次射击扣真实资源，客户端只显示状态，当前匣与备用资源分开记账，耗尽或退出则结束。

无匹配资源：不激活，明确「没有可用的匹配弹药」。有箱或有备用余弹都可激活。提示：「超限弹匣」已激活，释放你的火力！结束：「超限弹匣」进入冷却。冷却中再双击：还需 X 秒。

结束条件至少：匹配箱和备用余弹耗尽；换枪；卸下武器；死亡；不可操作；进入原版换弹；连接/会话代际变；达到最长持续时间；主机发现资源指纹不一致。优先：**资源耗尽即结束，另加固定最大持续时间**。玩家手动再双击是否取消，本票不强制。持续秒数与超限冷却秒数：**本票不钉**。

逐发供弹如何在不破坏原版射击权威下实现 = **Speculative**，必须先做可行性研究（见本图 [超限弹匣逐发供弹可行性](14-r6-overlimit-supply-spike.md)），不能在实施票里写成「跳过当前匣扣弹」。本票产品语义仍冻结。

### Q6 — 全部留在更好的换弹体验

不新 FeatureId、不新生态技能接口。U3DS 不画 U 菜单和 HUD，仍执行压弹、后台自动压弹、超限供弹的权威逻辑。

### 本票不做 / 待定

不做：新官方「技能系统」；占用原版 22 槽；把当前匣压过 MaxAmount；一级删技术闸；用尸潮条坐标当弹药 HUD；被动整理触发合匣或超限。

待定（不挡本票关闭，挡超限实施）：每级经验；0 级与超限的冷却秒、超限最长持续；逐发供弹 spike 结论。

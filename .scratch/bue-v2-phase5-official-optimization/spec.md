# BUE Phase-5 规格：现有官方功能优化定界与接线

Status: ready-for-agent
来源：`.scratch/bue-v2-phase5-official-optimization/map.md`（completed）+ V5-T1..T8 决策票 Answer + V5-R1..R8 研究报告 + `CONTEXT.md`；本规格只把已裁决内容成文，不重开已关闭争议。
当前对外部署基线：契约 2.1 / RELEASES 行 13 / 候选 `AF1F50C9…16D0`。本阶段契约只消费 2.1，不扩 `IFeatureRegistration`，不新增 FeatureId。

## 事实基线（已建成事实与本阶段缺口）

1. Phase-4 已把管理面板草稿/保存、功能级启停、LIT 标题栏单「整理」、模式/方向两条 Choice 接到 2.1；POST-P4 可见修复已随行 13 发布。游戏内表面继续用原版 Glazier。BueUi 不是模块，也不是 Glazier 的别名。
2. 整理求解器仍是迁入时的 `default-grid-v1`：同类/空间/大件 × 降序/升序；O-LIT-1 挂账未改算法。策略层只转发。标题栏只注入玩家服装页；STORAGE 现网不注入；协议对 page=7 当畸形包拒。
3. 被动整理未进生产：原插件 v1.4.1 摘掉 Harmony 特性硬禁用；BUE 红测断言类型缺席。现网整理入口只有标题栏按钮。拾取/合成走主机 `tryAddItem`；Ctrl+右键玩家↔容器走 `sendDragItem`，不经 `tryAddItem`。
4. 容器第 7 页是挂载槽，不是身份：世界箱子单 opener，后备箱跟驾驶座。工坊虚拟容器无识别字段。Ctrl+全身整理不含仓储栏。
5. LIR：功能 A = 整理成功后同 ID 匣合并（不填箱）；功能 B = 双击 R 用弹药箱填背包未满匣（页 2..6），**不写枪上匣 / `ammo` / `state[10]`**。设置 facet 已空，只剩生命周期启用。原版弹药 HUD 只画当前/上限。原版技能树加不进第 23 槽；`askSpend` 可花经验。
6. 给人看的开发手册是空槽。生态作者按规定只读 SDK + NoOp。抢权威的是未退役 `.scratch` 长文。
7. R6/R7/R8：完整超限供弹（逐发拆账、空匣连发、先灌枪再冻匣）在原版射击权威下本阶段做不到。

## Problem Statement

玩家整理背包时仍看到三种内部模式，排出来的格子不像按用途分段的记忆结构；打开箱子没有「整理」，点全身整理也不会动箱子，旧插件还曾出现可点但主机拒。捡东西或 Ctrl+右键因为碎洞失败时，东西就留在地上或原处，不会为这一次操作重排。弹药只显示匣内/上限，看不出还有几本有弹的匣和后备一共多少发。双击 R 人人能用，没有技能进度。第一次写生态插件的人会被 SDK 长文和过期 `.scratch` 规格吓到，没有一图流入口。

锁定和完整超限（空匣也能打、边打边从箱子扣）玩家会想要，但本阶段不能做成半成品按钮或免费伤。

## Solution

只优化已有官方功能，不新 FeatureId。背包整理换成唯一的标签分段、行带排版；容器按会话整理当前打开的世界箱或已授权后备箱；入包失败和 Ctrl+右键失败各走一条恢复，只整理该操作需要的那一侧；弹药 HUD 在原版数字旁追加有弹匣本数和后备发数；换弹技能只到 0～2 级，花原版经验，界面在 U 菜单战斗区下方（接不上则降到该功能设置页）。给人看的开发手册放进 `docs/developer/`，SDK 仍是契约唯一事实源。

从使用者视角：点「整理」得到按用途分段、空位收在右下的布局；开箱能整理这只箱子；碎洞时捡得进、Ctrl+右键能挪进；瞄具旁能读后备；换弹可以升级冷却和自动再压一轮。完整超限和装备栏锁定明确留到以后。

## User Stories

1. As a 玩家, I want 点「整理」后物品按固定用途标签从左上往右下分段、空位收在右下, so that 我能靠位置记住弹药和医疗在哪，而不是猜三种内部模式
2. As a 玩家, I want 不再在设置里看到同类/空间/大件决定算法, so that 我不会以为还在选三种整理器
3. As a 玩家, I want 整理要么整页合法成功、要么明确失败且格子不动, so that 我不会丢掉能放下的东西，也不会看到重叠
4. As a 玩家, I want 当前栏整理和 Ctrl+全身整理用同一套排版, so that 全身整理不会突然换一种摆法
5. As a 玩家, I want 打开世界箱子或已授权后备箱时标题栏有一颗「整理」、只整理当前这只容器, so that 我不必先把东西掏到背包再排
6. As a 玩家, I want Ctrl+全身整理永远只动身上五页、即使箱子开着也不卷进去, so that 「全身」的意思稳定
7. As a 玩家, I want 点容器「整理」后若箱子已关、没权限或内容变了，看到中文原因且东西没被改, so that 不会再遇到可点但没动静
8. As a 玩家, I want 工坊虚拟箱不画整理按钮, so that 我不会点一个主机根本不认的控件
9. As a 玩家, I want 捡东西或合成因碎洞失败时，身上五页被重排一次并再试放入, so that 两格物品对两个碎一格时仍能进包
10. As a 玩家, I want 重排后仍放不下时东西留在地上、背包也不变, so that 不会出现报成功却吞物
11. As a 玩家, I want Ctrl+右键因目标碎洞挪不进去时，只整理接收的那一侧再试这一件, so that 我不必先手动点整理再转移
12. As a 玩家, I want 这些自动恢复成功后不要突然压弹, so that 捡一件衣服不会当成我点了「整理」
13. As a 玩家, I want 停用背包整理后，按钮整理和两条恢复都回到原版, so that 我关功能就是关功能
14. As a 玩家, I want 原版弹药数字旁边看到有子弹的备用匣本数和后备总发数, so that 我不用翻背包估还能打多久
15. As a 玩家, I want 0 级仍然能双击 R、只是多一段技能冷却, so that 升级不会把我现在的压弹抢走
16. As a 玩家, I want 1 级去掉那一段额外技能冷却、但连点仍被技术闸拦住, so that 手感更快又不会连发请求
17. As a 玩家, I want 2 级在双击成功后再自动压一轮, so that 我不用为同一场战斗按两次，同时整理后合匣仍然独立存在
18. As a 玩家, I want 在 U 菜单战斗区下方看到换弹技能并用原版经验升级, so that 我不必另学一套技能树，也不会占掉原版槽
19. As a 玩家, I want 本阶段不要出现叫「超限」却只是压弹或能空匣白打的按钮, so that 名称和手感一致
20. As a 玩家, I want 本阶段标题栏不要出现半成品锁定钮, so that 我不会以为某页已经防掉落或跳过整理
21. As a 生态功能作者, I want 先读 `docs/developer/` 的一图和三短章再链到 SDK 与 NoOp, so that 我不必把过期 `.scratch` 长文当成契约
22. As a 人类贡献者, I want 开发手册不复制 SDK 码表、范例只导读 NoOp, so that 契约更新时不会有第二份会漂的全文
23. As a 仓库维护者, I want DEV-V5-01 先交出手册、02 先形成排版模块、03–05 只消费该模块, so that 容器和恢复不会各自复制算法
24. As a 仓库维护者, I want 01..07 不授候选、08 出唯一对外候选且契约仍为 2.1, so that 台账身份唯一
25. As a Headless 服务端, I want 不画整理按钮、HUD 和 U 菜单, 但仍执行容器整理请求、入包恢复、压弹和技能扣经验, so that U3DS 有权威行为而不是只靠「没画面」
26. As a 联机主机, I want 容器整理和恢复都带会话与版本、失败零修改, so that 客机不能本地改格子冒充成功

## Implementation Decisions

以下全部来自 V5-T1..T8 已裁决条目。冲突时以对应票 Answer 为准。本规格不发明新 FeatureId、不新增公开契约成员。经验数值与 0 级冷却秒数是实施票**必填参数**，禁止用猜测默认值过门。

### 共享规则（V5-T1）

- **契约**：六块优化落在官方功能 internal 或文档层。公开契约保持 2.1 零扩面。手册不是契约。`public` ≠ 契约。生态不登记锁定、整理策略或换弹技能。
- **官方先行消费**：背包整理消费排版、容器、两条恢复；更好的换弹体验消费 HUD 与 0～2 级技能。NoOp 不替代。
- **STORAGE**：授权重开第四阶段「不注入 STORAGE」。新边界是容器会话，不是把页上限改成 7。
- **Headless**：画面类（按钮、HUD、U 菜单、锁定——本阶段无锁定）U3DS 不画、不抛、不写客户端草稿。权威行为（容器整理请求、入包恢复、压弹、扣经验）主机必须真做。
- **文档顺序**：先手册票关闭 → 用户目视可外发后请第三方评审 → 官方功能实施可与评审并行。评审不挡本规格闭包，也不挡 02..08。
- **本图范围外**：新 FeatureId；BueUi；三模式当算法档；被动整理挂拖放；Prefix 内死开关；全身整理含容器；可点但静默失败；锁定半成品；用压弹/冻匣/免费伤冒充超限。后续另开图 ≠ 永不。

### 给人看的开发手册（V5-T2 → DEV-V5-01）

- 四层不增层。落点 `docs/developer/`（README 入口 + 手册），不进 `docs/sdk/`。玩家手册与开发者手册分开。
- 形态：一张总图 + 三短章（模块结构、最小接入流程、NoOp 导读）。禁止码表、版本账、决策过程、阶段票号、`.scratch` 正文、官方业务实现细节。
- 可运行范例唯一来源 = 现有 NoOp。手册只指路。与 SDK 冲突以 SDK 为准。
- 官方四件只点名「在主 DLL 内，不是生态要接的模块」。
- 会抢权威的 `.scratch` 长文加 SUPERSEDED / 历史资料标，不删文件。
- 评审包 = 该目录 + README 开发者入口，不整本重审 SDK，不含 AI 规格。

### 统一排版（V5-T3 → DEV-V5-02）

- 唯一官方整理方法：玩家用途标签分段、行带、右下留空。同时重写排序与放置，不做全局最优装箱。
- 硬性先于视觉：不重叠、不越界、不丢物、能放下必须放下、失败不提交半成品。
- 对外一个深模块：输入 = 物品集合 + 网格 + 少量稳定偏好；输出 = 确定性计划或明确失败。分类、标签序、主体、行带、并排、旋转、右下评分、稳定收尾、合法性验证全部内部。
- 不新增玩家策略选择器，不给第三方加载。内部标识可叫 tagged-row-band-v1，不进玩家界面、不进契约。旧同类/空间/大件与升序/降序仍可读，首次归一后不再决定算法。标题栏仍只留「整理」。
- 玩家用途标签顺序冻结：远程武器、弹匣、医疗用品、近战武器、投掷物、弹药、弹药箱、枪械配件、食物、饮水、工具、服装与防护装备、背包与容器、燃料、补给与制作材料、建造、设施与陷阱、地图与指南针、钥匙、其他。不是 `EItemType` 枚举序。弹药箱按给弹匣供弹的蓝图认，不单看 SUPPLY。分类失败进「其他」，不得丢物。
- 横向并排必须可计算。主体不能只按高度。`TryPlanLayout` 规划不改真实背包。
- 当前栏、全身整理、容器整理、两条恢复凡执行背包整理都必须消费本模块，入口不得复制算法。
- 旋转：默认正向（文字可读）；仅当明显改善、避免漏放或死洞时才转，尽量整组统一。

### 容器会话整理（V5-T4 → DEV-V5-03）

- 第 7 页只是挂载位置，不是身份。禁止「页号等于 7 就整理」。
- 本阶段两类：当前合法打开的普通世界容器；当前玩家已获授权的车辆后备箱。必须两个 adapter 证明 seam。虚拟箱、地面摊、主副手、装备槽本阶段不支持；虚拟箱投影 Unsupported，不画按钮，留下原因。
- 打开且能力为可用时，容器标题栏一颗「整理」，只整理当前容器网格。布局由容器标题栏 adapter 提供，不复用服装页 -130。Ctrl+全身永不含容器。
- 请求绑定种类、会话身份、请求者、版本/指纹。提交前主机重验。过期或失败零修改，中文原因可见。按钮可见 ≠ 授权承诺。不另造 BUE 整理锁。
- 本阶段容器不画锁定，不做容器侧「捡进箱子就被动整理」（Ctrl+右键接收侧恢复是另一条 adapter，见下）。

### 入包恢复与快速转移恢复（V5-T5 → DEV-V5-04 / DEV-V5-05）

- 两条 adapter，共享排版、版本校验、零修改失败；触发语义不同。跟随背包整理生命周期，无独立开关。禁止 Prefix 内死开关。不挂更好的物品交互拖放预览。
- **入包恢复**：主机拾取/合成 `tryAddItem` 失败后，把玩家五页 + 待加入物品一起规划，再试放入。第一版只接线已验证的主机拾取/合成；其它获得路径另裁。排除主副手、AREA、容器页。
- **快速转移恢复**：Ctrl+右键因目标碎洞失败（含客户端 `tryFindSpace` 失败而未发包）。原版玩家↔容器是 `sendDragItem`，**不经** `tryAddItem`，不能靠入包补丁看见。只整理接收侧：玩家→容器则整理当前受支持容器；容器→玩家则只整理原版选定的那一玩家页。地面摊 Ctrl+右键进容器是拾取 RPC，归入包路径。
- 恢复成功必须：待加入/待转移物品在计划中；合法；版本有效；主机提交成功。否则原版失败语义 + 零修改。禁止吞物。禁止转移失败但目标已被单独整理。
- 成功不发布整理完成，不触发整理后自动压弹，不新增公开事件。

### 弹药 HUD 与换弹技能 0～2（V5-T7 → DEV-V5-06 / DEV-V5-07）

- 全部留在更好的换弹体验，不新 FeatureId。进度、运行状态、HUD 投影分三层，不得混成一个设置字段。
- **HUD**（功能启用即有）：原版当前/上限保留。旁加有弹匣 N（身上五页、口径匹配、amount>0 的备用匣本数，不含枪上那本、空匣、容器、地面）与后备弹药 M（这些匣余弹 + 能经 FillTargetItem 给当前匣供弹的箱，匹配同现网 LIR）。只扩展右下弹药信息区。不改枪模小字。不与尸潮条抢顶栏。U3DS 不画。
- **等级**：0 基础（双击 R + 较长技能冷却）；1 快速换弹（取消额外技能冷却，保留技术安全闸）；2 自动压弹（双击成功后固定等待再自动压一轮，建议 8s，本阶段不可设）。视觉在原版 U 菜单战斗区下方追加分区；事实由 LIR 按玩家/角色持久化，不写入原版技能数组。升级花原版经验，主机检查后扣。新档不送等级。U 菜单接不上则降为该功能设置页，属同一产品意图的另一种表面，不是改范围。
- 技术安全闸（现网约 1.5s 防重复提交）一级也不得删。技能冷却中再双击：红色剩余秒数，以主机为准。
- 功能 A（点「整理」成功后同 ID 匣合并）保留，与二级不是同一条。恢复路径仍不触发 A。
- **三级完整超限不进本阶段**，不进技能 UI，不留占位。R6/R7/R8 为延期证据。

### 装备栏锁定（V5-T6）

- 本阶段不做。不画、不留空、整理路径不读锁定、主机不接收锁定字段。未来 A 整理锁定与 B 防误触必须拆开。

### 实施纪律（V5-T8）

- DEV-V5-01 手册先行。02 先形成排版模块。03–05 只经布局计划消费。03 先形成容器会话 seam（两个 adapter）。04 与 05 两个恢复 adapter。07 两种表面是 presentation adapter。08 才唯一对外候选并更新 RELEASES。01..07 构建产物不是玩家可用候选。
- 官方功能票依赖 01 关闭，不依赖第三方评审回来。

## Testing Decisions

只测外部行为，不测求解器私有比较器名字或 Glazier 控件树。优先已有接缝：整理计划成功/失败、权威页范围、生命周期启停、LIR 压弹事务、面板设置行。新接缝只加在模块边界：`TryPlanLayout`、容器会话能力投影与提交、两条恢复 adapter、HUD 投影、技能等级读写。

好测试：

- 排版：给定物品集合与网格，计划不重叠、不越界、集合一致；失败零提交；标签不穿插；确定性。准备 T3 列出的输入类型（同 ID 医疗堆、细长混放、并排、换行、旋转改善 vs 更差、「其他」、弹药箱 vs SUPPLY、放得下却重叠失败不得再现）。不要求旧坐标黄金表。
- 容器：世界箱与后备箱两条 adapter；page=7 不是身份；关箱/换 opener/离座/版本过期零修改且有结构化原因；虚拟箱不画；Ctrl+全身不含容器。
- 入包恢复：仅 tryFindSpace 失败触发；成功放入不排；仍放不下则原版失败 + 背包未改；不发整理完成。
- 快速转移：不经 tryAddItem 的路径仍能请求恢复；只改接收侧；失败源和目标都不变。
- 生命周期：功能停则两条恢复与按钮均不执行；禁止停用后 Prefix 仍在且靠 if 短路就算关。
- HUD：N/M 定义与「不含枪上匣」；功能停不画。

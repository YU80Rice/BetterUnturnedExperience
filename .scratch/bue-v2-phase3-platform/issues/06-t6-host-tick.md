## Question

宿主时钟已入 Contracts 冻结面（DEV-V2-19，官方/生态同权获取时钟）。本票裁决是否/如何进一步开放为生态公共调度能力。风险级 **Worth exploring**。按六问结构：

1. **现状评估**：HostTick 现行面（频率/阶段/序号/时间增量不变性）对生态真实需求够不够——缺什么（每模块节流？相位错开？暂停感知？）；
2. **调度语义**：是否需要 per-feature 调度参数（频率协商/预算），还是维持统一时钟 + 功能侧自节流；
3. **实施深度**：本阶段做哪层；
4. **留到后续**：哪些明确不做（BueThreading 后台任务/队列上限/取消属愿景后续级，是否顺手纳入？）；
5. **契约影响**：扩面即升版本；
6. **同权影响**：调度参数官方/生态是否同权申请。

事实输入：V3-R1。主源：CONTEXT「宿主时钟」、DEV-V2-19 票、愿景 BueThreading 行。

## Answer

2026-09-09 用户+PM 六项裁决全部定音，**方案 A（统一时钟+功能自节流）通过**。deepening 目标=把宿主 Tick 收敛成小而稳定的时序 interface：宿主负责产生/去重/线程/异常隔离，功能负责自节流；生态只需理解三个载荷字段与订阅/注销语义。

### 1. 调度语义 = 统一宿主时钟，功能侧自节流（方案 A）

`HostTick` 频率=宿主 Update 泵实际产生频率；BUE 不承诺独立固定 Hz，不提供 per-feature 频率协商/相位错开/平台预算/低频派发过滤/派生 10Hz 时钟。低频功能自行用 DeltaTime 累计或 TickSequence 差值决定何时执行工作；**LHT 的 10Hz HUD 自节流=官方先行消费与推荐模式**。理由：载荷小、每拍一 tick 成本可接受、自节流有官方先例、per-feature 调度会新增频率/暂停/恢复/背压/公平性语义、无真实需求证明需要扩约。

### 2. 低频需求增多时的处理

SDK 登记「需要低频执行的功能应订阅 HostTick 后在功能内部自节流」，文档含：累计时间阈值模式/序号差值模式/首拍处理/DeltaTime 回拨已钳零/模块停止清理自身节流状态/不得自建第二个 Unity Update 泵。未来若多个真实功能重复同一低频模式且产生可量化收益，再立「派生低频时钟/调度参数」票——当前只登记为地图雾区，不预建 implementation、不提前扩约。

### 3. 现行 HostTick 契约登记（本票主要交付面，八条）

①**宿主产生与身份**：Tick 只能由 BUE 宿主产生（保留宿主身份），功能/生态都不能伪造——T3 事件类型归属与宿主身份检查继续生效；②**每拍恰一 tick**：每泵拍最多一个、同帧多驱动源不重复产生（去重=宿主 implementation 责任），订阅者无需自行去重正常宿主输出；③**Phase 语义**：Phase=Update、数值=0 冻结；更多 Phase=未来加性扩展不得隐式增加；④**序号**：从 1 开始严格递增、正常运行不重置、功能不可修改、模块 LifecycleGeneration 变化不改变序号语义；⑤**DeltaTime**：相邻 tick 时间差、回拨/负差钳零、不承诺固定帧间隔、暂停期间 Update 不产生 Tick、恢复后下一拍反映实际间隔（是否忽略大间隔由功能自决）；⑥**载荷范围**：只含 Sequence/DeltaTime/Phase——不得携带业务字段/网络消息/设置值/玩家状态/功能命令/诊断载荷；⑦**异常语义**：派发不把单订阅者异常抛回宿主泵调用方——结构化诊断→按 T4 功能级隔离→其他订阅者继续（`bool` false 只表达宿主已记录处理失败，不要求调用方处理模块内部异常）；⑧**主线程保证**：构造性保证（宿主 Update 链→HostTick），不通过时钟内部线程/隐藏后台线程产生——生态可在 HostTick 回调安全调用主线程限定游戏 API；后台任务能力不属本票。

### 4. 实施深度 = 现状加固三件

①契约登记（产生者/身份/每拍一次/Phase/序号/DeltaTime/载荷范围/异常/主线程/泵频率/自节流推荐模式）；②红测补齐：暂停期间无额外 Tick、恢复后 DeltaTime 正确、负差钳零、序号从 1 严格单调、同帧多驱动源只一 Tick、宿主身份冒发被拒、订阅者异常不扩散、异常进结构化诊断、停止自动注销（现有 R3-Spec DeltaTime 单调钳零行为继续作回归锚）；③NoOp 契约 probe 补 HostTick 支线：注册→取订阅入口→收到 HostTick→检查 Sequence/DeltaTime/Phase→停止→自动注销。

### 5. 留到后续

per-feature 调度参数、派生低频时钟、更多 Phase、后台任务、取消令牌、后台队列容量、背压、调度公平性、功能优先级、专用性能预算——**全部等待真实需求信号**，不因「将来可能需要」提前加入。BueThreading 后续单独规划；T5 主线程 dispatcher ≠ 完整后台线程平台。

### 6. 契约影响与同权

**本票零新增契约面、不触发契约版本变化**（HostTick 已在 DEV-V2-19 冻结；只写 SDK+补测试+补 probe；不改载荷/Phase/订阅方式/线程模型/不加调度参数）。实施中若发现必须加新 Phase/载荷字段/调度参数/订阅形式→另行评估至少按 Minor 加性处理，不得本票内隐式落地。同权三条：官方与生态同一 HostTick 订阅 seam；LHT 官方先行消费证明统一时钟可用；NoOp probe 验证生态订阅/回调/停止注销。补充：**官方功能不得获得特殊 Tick 频率、生态功能不得被宿主静默过滤**——双方按相同主线程/序号/DeltaTime/异常隔离规则运行。

### 本票不做

per-feature 频率协商、派生低频时钟、更多 Phase、独立 Hz 承诺、BueThreading、后台任务/取消/队列上限、暂停感知新概念、修改已冻结 HostTick 载荷。

## 总图：两层结构 · 一条生命周期主线

```text
【谁装什么】

  BepInEx\plugins\
    BetterUnturnedExperience.dll ← 玩家装的唯一官方文件
    │   内部：四个官方源码模块构建期聚合成这一个 DLL
    │         （更好的物品交互 · 背包整理 · 更好的换弹体验 · 更好的尸潮播报）
    │         ——它们在主 DLL 内，不是生态要接入的模块
    │   对外：冻结的插件 GUID 与程序集身份 + 公开注册桥 + 平台服务
    │
    YourEcoFeature.dll           ← 生态作者的独立 BepInEx 插件，发布包只含自己

【一条生命周期主线（你的 DLL 的视角）】

  BepInEx 发现插件（原生扫描/实例化，BUE 不自建加载器）
    → [硬依赖] 保证 BUE 先装载、注册窗口已开
    → 你的 Awake：经公开注册桥提交注册对象
        ├─ 显式拒绝 → 按 SDK 的处置剧本降级，不假装注册成功
        └─ 显式受理 → 登记在册待启动
             （宿主稍后冻结注册目录、批量启动功能——冻结与启动不以你的注册为开关）
             → 模块工厂 Create()
             → Start(IFeatureBootstrap)   ← 平台能力在这一刻注入到手
             → 运行：功能事件 · 网络 · 宿主时钟 · 设置 · 诊断
                     · 生命周期查询 · 主线程投递 · 依赖查询
             → Stop(停止原因) 或 故障隔离  ← 宿主负责善后（释放资源、注销订阅）
             → 用户重新启用 = 新代际       ← 旧代际的一切句柄全部作废
```

图下三句话：

1. 玩家永远只装一个官方文件；你的插件是第二个文件，两层互不混装；
2. BUE 对你而言是**前置库与运行时平台**——发现、加载、排序都是 BepInEx 的原生职责，BUE 不扫描你的 DLL；
3. 你与平台的耦合只有两处：**注册**（Awake 期，一次）与**能力到手**（Start 期，一组注入视图），其余时间你就是普通 BepInEx 插件。

## 短章一 · 模块结构

### 三层职责

- **官方功能（第一层）**：更好的物品交互、背包整理、更好的换弹体验、更好的尸潮播报——四个官方源码模块，构建期聚合进主 DLL。它们是「在主 DLL 内」的存在，不是第三方要注册、加载或替换的模块。
- **BUE 平台面（你的前置）**：三样东西构成你对 BUE 的全部依赖——冻结的插件 GUID 与程序集身份、公开注册桥、一组平台服务（事件、网络、宿主时钟、设置、诊断、生命周期、主线程投递、依赖查询）。哪些承诺、哪些明确不承诺，逐条看 SDK §2、§3。
- **生态功能（第二层，就是你）**：你自己的独立 BepInEx 插件 DLL，带自己的 `[BepInPlugin]` GUID；你的安装说明里，BUE 是玩家另行安装的前置。

### 一个模块几时活、几时退

- **注册（存在声明）**：在你的 `Awake` 里经公开注册桥提交注册对象。注册受理≠启动——此刻你是「待启动登记在册的功能」；宿主冻结注册目录之后再注册会被显式拒绝。
- **获得能力（开工时刻）**：宿主批量启动时调用你模块的 `Start(IFeatureBootstrap)`，平台能力以**一组注入视图**交给你：事件订阅/发布、事件类型登记、网络、宿主时钟、设置、诊断日志、生命周期状态查询与资源跟踪、主线程投递、依赖目录。每条缝的逐条语义与可用条件，以 SDK 附录 A 为准，这里不展开。
- **运行（被缝驱动）**：你的节奏来自你订阅的东西——宿主时钟的拍、功能事件、网络帧。**不要自建 Unity Update 泵，不要自建线程泵**。入站网络回调运行在传输泵线程上，不得直接碰游戏世界对象；要回主线程，走平台的主线程投递缝。
- **退出（宿主善后）**：停止或故障隔离时宿主调用你的 `Stop`，随后自动逆序释放你登记跟踪过的资源、统一注销你的全部订阅。所以：**不自拆订阅、不把清理写成私有仪式**——交给宿主是契约行为。单个功能抛异常只隔离该功能，不炸宿主、不波及其他功能。
- **再启用 = 新代际**：隔离的功能不会自动重启（只有用户在管理面板显式启用才臂起）；新代际开始时，旧代际的视图、句柄、订阅一律作废——这是「别跨代持引用」的原因。

## 短章二 · 最小接入流程

六步方向，一步一句话；**权威原文与逐条规则在 SDK §4（接入六步），发布前核对 SDK 附录 C.6（上架自检清单）**——这里只告诉你每步在忙什么：

1. **建独立 BepInEx 插件项目**：你的 `[BepInPlugin]` GUID 是你自己的。不复用 BUE 的 GUID，也不把功能源码塞进 BUE 仓库请求聚合——官方是源码模块，生态是独立 DLL，两层不混。
2. **声明前置**：`[BepInDependency]` 指向 BUE 的插件 GUID，硬依赖。它保证 BUE 先装载；BUE 缺席时你的插件根本不会启动——fail-closed 是特性，不是 bug。
3. **编译期引用主 DLL**：只引用 `BetterUnturnedExperience.dll` 本体，`CopyLocal=false`，发布包只含你自己的 DLL。把 BUE 捆进你的包，是玩家侧双装问题的主因。
4. **Awake 经公开注册桥注册**：实现注册对象——携带功能定义工件、模块工厂、最低契约版本（对齐你要兼容的目标 BUE，当前值见 SDK §7）——然后调用 `BueRuntimeHost.Register`。注册返回**显式的受理或拒绝**：消费这个结果并据此降级，是生态作者的第一条纪律；被拒的逐因处置看 SDK 附录 B 的拒绝码表。
5. **Start 里干活**：出站消息先登记自己的频道才能发；自己的事件类型先登记归属，才谈得上发布与订阅；节奏订宿主时钟；设置与日志用注入视图读写，不另造配置格式、不直写持久化文件；自己 new 出来的可释放资源交给生命周期缝跟踪登记，让停止边界能替你收拾。
6. **退出纪律**：`Stop` 里不拆订阅（宿主统一注销）、不留旧代际句柄、不假设注册必成、不假设自己永远活着。

两条身份纪律一句话版：**FeatureId 用你自己的反向域名**（官方保留段里的名字会被确定性拒绝，冒用不会成功）；**诊断码别用平台保留前缀**（生态诊断码从你的 FeatureId 派生，示例见 SDK 附录 B.9、B.10）。

## 短章三 · NoOp 范例导读

仓库里唯一的可运行范例就是活样板 [`src/BetterUnturnedExperience.NoOpFixture/`](../../src/BetterUnturnedExperience.NoOpFixture/NoOpFeaturePlugin.cs)——独立 GUID + 硬依赖前置 + 经公开桥注册，长期被宿主测试在真实宿主组合下验证。本手册不复制第二套接入代码，只带你读它。按这个顺序看（都在 `NoOpFeaturePlugin.cs` 一个文件里）：

1. **入口类与两个属性**：`[BepInPlugin]` 自带 GUID、`[BepInDependency]` 硬依赖 BUE，`Awake` 里注册并把返回结果原样打进日志——「检查显式结果」的姿势就在这一行；
2. **注册类**：实现 `IFeatureRegistration`（功能定义工件、最低契约版本、模块工厂、客户端 UI 卫星位），并示范了**设置 facet 用额外接口声明**的可选面姿势——不声明设置的功能，拿到的设置视图就是诚实的 null；
3. **模块 `Start(IFeatureBootstrap)`**：按固定顺序走查每条缝——Bootstrap 完整性 → 事件类型登记与订阅自发自收 → 资源跟踪登记 → 网络通道登记与发送（无会话时拿到的是**显式降级结果**，不是异常）→ 时钟订阅 → 设置读快照与显式提交 → 诊断日志三方法。每条缝都对应 SDK 附录 A 的一节；
4. **`Stop`**：空实现。清理职责在宿主——这本身就是教学点。

**必要代码 vs 测试辅助**：作者需要照抄的骨架只有四件——入口属性、注册类、模块类的 `Start`/`Stop`。样板里大量的 `ProbeState`、故障旋钮、分缝判据、观测静态量，是宿主测试把它当**生态侧统一探针**用的脚手架，不是生态功能的必选项，搬回你自己项目前请删干净。

它的 FeatureId（`io.github.yu80rice.bue.noop`）是官方白名单里的**样例身份**——你照抄骨架时第一件事就是换成自己的反向域名。

**范例地位声明**：该样板用于展示最小接入路径，**不扩展 SDK 契约**；它与 SDK 不一致时，**以 SDK 为准**。
